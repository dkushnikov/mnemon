# Mnemon Knowledge Vault

Personal knowledge extraction vault. Sources are captured and extracted by the engine into structured knowledge artifacts; the owner thinks on top of them. The store mechanics are defined once, in the engine: `$MNEMON_HOME/docs/specs/2026-10-16-vault-store.md`; `_meta/Protocol.md` is its short form, and where this file and the spec differ, the spec wins.

## Structure

- `Sources/` — one folder per captured **revision**: `YYYY-MM-DD_{hash8}/` (`-2`, `-3`… for further revisions of the same resource) with `source.md` + `extract.md`. Written by the engine only
- `index.md` — regenerated by `mnemon reindex`; never edited by hand (a durable note on a row goes to `index_note:` in `extract.md`)
- `Synthesis/` — the owner's thinking across sources (`status: seed → draft → stable`). An agent writes here only on explicit request, and only `seed` or `draft` notes marked `drafted_by: <agent>`; `stable` is the owner's act
- `_inputs/` — incoming material: sessions and producers drop it, sessions drain it; a queue is declared with `type: queue` and `since: <date>` in its frontmatter
- `_meta/charter.md` — the owner's intent: purpose, the declared capture contexts (`## Contexts`), the value scale, the ratification radius (`## Radius`). Owner-only
- `_meta/reader-context.md` — the reader's context (role, domains, goals) that frames every extraction; an agent updates it on request, under the freshness protocol (`synced:`)
- `_meta/Protocol.md` — the short form of the store spec: folders, ownership, states, the doctor's checks, doors
- Bases, Templates and the vault's own notes — the owner's and the agent's working surface, outside the engine's files

## Principles

1. **source.md is immutable.** Once published, never modified — its body is the captured text byte for byte, and its `capture.text_sha256` lets the engine detect an edit (`integrity-error`). Re-capture = new folder (`mnemon add --recapture`), the old one stays and is named in `supersedes:`.
2. **The engine extracts; the owner synthesizes.** The engine publishes `source.md` (what was captured) and `extract.md` (validated model output). A Synthesis note is the owner's thinking. An agent asked to help writes a `seed` or a `draft` with `drafted_by: <agent>` and leaves `status: stable` to the owner — ratification is a human act, never a default.
3. **The radius bounds agent production.** Unratified drafts and open seeds are counted by `mnemon doctor --data` against the charter's `## Radius` (`seeds: N open · D days`, `drafts: N unratified · D days`, `queues: D days`). An agent that drafts faster than the owner ratifies is producing debt, not knowledge: before adding a draft, look at `mnemon status --brief` — when the radius is crossed, propose ratification or pruning instead.
4. **Key Ideas are atomic.** Each one stands alone, domain-tagged, max 16 words.
5. **Extraction is personal.** Every extract is framed by `_meta/reader-context.md` — not generic.

## Doors — who writes what

The engine is the only writer of `Sources/`, `index.md`, the archive and its ledger. Humans and agents write the vault only through these doors:

| Door | Who | Rule |
|---|---|---|
| `extract.md` frontmatter — **only** `status`, `index_note`, `title`, `tags`, `domains`, `people`, `visibility`, `rating` | owner, agent | the curation subset; the body and every other field are the engine's |
| `Synthesis/` | owner; agent on explicit request | agent notes are `seed`/`draft` with `drafted_by: <agent>`; `stable` = owner |
| `_inputs/` | sessions, producers | incoming material; declared queues; drained by sessions |
| `_meta/charter.md` | owner | contexts, value scale, radius |
| `_meta/reader-context.md` | owner; agent on request | the freshness protocol (`synced:`, `staleness_threshold_days`) |
| Bases, Templates, the vault's notes, this file | owner, agent | ordinary vault files |

Everything else — a `Sources/` folder written by hand, an edited `source.md`, a hand-edited `index.md`, a file in the archive — is a defect the doctor reports.

## How captures land

`mnemon add` (the gateway) fetches the content itself — its own fetch chain and `defuddle` / `pandoc` / the DOM text for pages, `pdftotext` for PDFs, `yt-dlp` / `whisper` for media, or the text it is given — and publishes `Sources/<revision>/source.md` with that text. It then runs a fenced extractor (`claude -p --restricted --tools "" --no-session-persistence --json-schema …`, prompt on stdin, no tools) that returns structured fields, validates them and publishes `extract.md`. The model never writes into the vault, and a session started in this vault is never the extractor — it is a caller: `RESULT:` lines and exit codes are computed from the files by the gateway. Automated feeders drop envelopes into an inbox directory for `mnemon ingest <dir>`.

**Completeness and site captures.** Every URL capture records how it was acquired and how much of the fetched page the conversion kept: `capture.acquisition` (`ok`, `thin`, `paywall`, …) and `capture.completeness` — `complete` (every substantial line and heading of the saved page is in the text), `partial` (something was lost; `missing_lines`, `glued_lines` and `headings_missing` say how much), `blocked` (a paywall teaser: only the text before the wall), `unknown` (nothing to check against: PDFs, media, plain text). Completeness is a diagnostic, not a gate — a `partial` source is a published source; read it as such before building on it. A site capture (`mnemon add --url <landing> --site <plan.json>`) is one source for the landing resource whose body holds every included page as `## Part n — <url> (<role>)`, with `folded_sources:` listing each page's disposition and completeness and `site_pages: "<converted>/<included>"`. The literal URL stays in `url:`; `canonical_url:` is the computed identity (tracking parameters and plain fragments dropped); a re-capture names its predecessor(s) in `supersedes:` and `mnemon reindex` marks the old index rows from it. A durable note on an index row belongs in `index_note:` of `extract.md`, never in `index.md` — its rows are regenerated (the replaced ones are kept in `_inputs/index-hand-edits-<date>.md`).

## Schemas

### source.md frontmatter
```yaml
type: source
source_type: <article|video|podcast|book|paper|idea|conversation|website|document>
content_format: <text|transcript|pdf|reference|markdown>
origin: <url|text|youtube|audio|pdf|file|book|idea|ref:vault>
url: "<source url>"               # when known, as given
canonical_url: "<computed identity>"   # URL captures: version 1 of the canonicalization rules
title: "<title>"                  # --title or the acquired page / PDF title
author: "<author>"
captured: <YYYY-MM-DD>
captured_by: agent
capture_id: "<capture operation id>"
resource_kind: <url|text|file|ref>
resource_sha256: "<identity of the captured resource>"
resource_id: "<hash8 — the folder label>"
revision: "<YYYY-MM-DD_hash8[-n]>"
supersedes: "<revision>"          # a re-capture; several predecessors are a block list
context: "<capture context, declared in the charter>"
capture:                          # how the text was produced; never written by the model
  method: "<direct+defuddle|direct+pandoc|render+dom-text|site+mixed|pdftotext|stdin|…>"
  fidelity: <exact|converted|transcribed>
  raw_store: <archive|state|none>
  raw_kind: <response|rendered|composite|transcript|file|site>
  acquisition: <ok|thin|js-shell|bot-wall|forbidden|login|paywall|…>   # what the fetch got
  completeness: <complete|partial|blocked|unknown>                     # what the conversion kept (diagnostic)
  missing_lines: <n>              # with glued_lines, headings_missing, repairs when a reference existed
  canonical_version: 1
  text_sha256: "<sha256 of the body>"
  text_bytes: <n>
```

### extract.md frontmatter
```yaml
type: extract
source_type: <matches source>
content_format: <matches source>
origin: <matches source>
visibility: <personal|public|company|private>
status: <extracted|dismissed>    # extracted = the engine's default; dismissed = your judgement (phase 3); captured/integrated are derived, legacy words are counted by the doctor
title: "<title>"
author: "<author>"
url: "<url>"
created: <YYYY-MM-DD>
extracted: <YYYY-MM-DD>
language: <en|ru|...>
tags: [<topic tags>]
people: [<mentioned people>]
domains: [<domain tags>]
rating: <1-10>
index_note: "<a durable note for the index row>"   # optional; the one hand-written field the index shows
capture_id: "<matches source>"
revision: "<matches source>"
capture_context:
  vault: <instance name>
  session: "<session>"
  intent: "<intent>"
  import_source: gateway
  import_batch: ""
extractor:                        # written by the gateway: schema, model, Claude Code version, template and input hashes
  schema: extract/1
  model: <model>
  claude_code: "<version>"
  template: <source type>
```

### extract.md body sections
1. **Summary** — 2-3 sentences, factual
2. **Executive Summary** — framed by reader-context.md, personal
3. **Key Ideas** — `- **Title** #domain — claim (max 16 words)`
4. **Connections** — wiki-style links to related topics
5. **Raw Quotes** — 3-5 best quotes from source

### Synthesis note frontmatter
```yaml
status: <seed|draft|stable>       # stable is set by the owner only
drafted_by: <agent>               # on every note an agent wrote; absent on the owner's own notes
created: <YYYY-MM-DD>
```
A note links the revisions it builds on as `[[Sources/<revision>/extract]]` — a link from a `stable` note makes a revision `integrated`, from a seed or draft `filed`. A note with neither `drafted_by` nor `status` has unknown authorship: the doctor reports it and excludes it from the radius.

## Don't

- Don't modify `source.md` after creation (the engine detects an edited body as `integrity-error`)
- Don't write `Sources/` folders by hand — `mnemon add` publishes them with their receipts
- Don't create a Synthesis note without an explicit request; when asked, write a `seed` or a `draft` with `drafted_by`, never `stable`
- Don't edit `extract.md` outside the curation subset (`status`, `index_note`, `title`, `tags`, `domains`, `people`, `visibility`, `rating`)
- Don't edit `index.md` — run `mnemon reindex`
- Don't write outside the doors above; don't touch the archive or the ledger
- Don't let the radius silently fill: when `mnemon status --brief` reports the drafts or seeds radius crossed, surface it before adding more
