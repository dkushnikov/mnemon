# Capture layer — resolve · fetch · convert · sanitize · check · site; canonical identity; media language; index regeneration; stage timeouts (phase 2)

**Status:** v1 draft for external review · **Program:** capture overhaul, phase 2 · **Builds on:** `docs/specs/2026-10-15-capture-contracts.md` v4.1 (phase 1; its contracts are not changed by this document, only extended where it says "phase 2") · **Closes:** #3, #4, #5, #6 and the phase-2 items of #11.

## Resume prompt

Phase 1 made the gateway honest about *what* it published (three artifacts, three hashes, receipts, a kernel-held lock, a fenced extractor). It did nothing about *whether what it published is the page*: `completeness: unknown` on every capture, one converter chain (`defuddle` → `pandoc`) that silently drops sections, arXiv from the abstract page, no multi-page capture, identity by the literal URL, YouTube captions in the wrong language, index rows frozen forever. This spec adds the capture layer underneath the phase-1 contracts: a python package `bin/capture/` with one network policy, a fetch chain (direct → rendered → external, the last only when the instance allows it), a three-way converter with a **diagnostic** completeness check against the saved raw, a sanitizer, site (multi-page) capture from a reviewable plan, per-host resolvers (arXiv full text, YouTube), a conservative versioned canonicalization that becomes the identity of url resources, stage timeouts, chunked extraction for oversized text, language-aware YouTube captions, and an index whose rows are regenerated from files.

## 2. Decisions

| # | Decision | Why |
|---|---|---|
| D1 | **The capture layer is a python package `bin/capture/`** (stdlib only, python 3.9): `policy.py` (network policy), `fetch.py` (fetch chain), `resolve.py` (canonicalization + per-host resolvers), `convert.py` (three-way conversion), `sanitize.py`, `check.py` (acquisition and conversion checks, inventory), `site.py` (map · plan · assemble), `report.py` (the report schema), `lib_table.py` (rowspan/colspan tables → pipe tables). Three CLIs the gateway calls: `bin/capture-fetch.py` (URL → raw file + fetch report), `bin/capture-text.py` (raw → capture-text + report; the phase-1 name and flags kept, schema v2), `bin/capture-site.py` (map · assemble). The gateway stays the orchestrator and the only writer of `source.md`. | bash cannot do DOM parsing or unicode alignment; one package keeps the five modules on one policy and one report. |
| D2 | **Acquire and convert stay two gateway steps.** `capture-fetch.py` writes the raw to the staged path the gateway names and never converts; `capture-text.py` converts a retained raw and never fetches. The phase-1 recovery rows hold unchanged: a conversion failure re-converts the retained raw, never refetches. | §3.4 of phase 1; "a converted page without its HTML cannot be verified or redone" (D8 of phase 1). |
| D3 | **One network policy, `capture/policy.py`, on every outbound request** of the engine: `capture-fetch.py`, the site mapper, the depth helpers (`kb_fetch.py`, `kb-probe-deeper.py` — rewritten over the policy, the `requests` dependency dropped), the arXiv metadata fetch, external fetchers (the URL handed to a vendor must pass the same checks). The policy: `http`/`https` only; no userinfo; the host of **every hop** is resolved and refused when any address is private, loopback, link-local, reserved, multicast or unspecified (`ssrf-blocked` / `ssrf-redirect`); at most 5 redirects, each re-checked **before** it is followed; a byte cap (`fetch_max_bytes`, default 20 MB; a capped download is an error, never a truncated raw); connect and read timeouts; one User-Agent (`fetch_user_agent`); no cookies, no credentials, ever. | the depth helper checked the host after the redirect (review); two fetch paths drift. |
| D4 | **The fetch chain is direct → rendered → external, and the raw of a rendered page is its post-JS HTML.** Direct = the policy's GET. Rendered = `render-url.sh --html` (headless Chrome) when the direct fetch is *blocked* or *js-shell* (acquisition check, D6) or when `--render` is given; the raw is the rendered DOM HTML (`<revision>.html`, `raw_kind: rendered`), so the same converters and the same reference apply (phase 1 kept rendered *text*; old `.txt` rendered raws stay reconvertible as before). External = Firecrawl (`/v1/scrape`) or Jina Reader, in the order of `external_fetchers`, **only** when the instance says `external_fetch: auto` (default `off`), only after direct and rendered both failed on a bot wall, a 403 or a JavaScript shell, only for a URL that passes the policy, with keys from the environment (`FIRECRAWL_API_KEY`, `JINA_API_KEY`); a fetcher without a key is skipped with a note. **Nothing in the chain is a way past a login, a paywall or a rate limit**: a login wall fails the capture, a paywall teaser is published as `blocked`, a 429 is retried later. The chain records every stage it tried. | program D7 (personal instance: auto-fallback for public URLs; a work instance: off); the Vercel checkpoint passed in headless Chrome, not in curl. |
| D5 | **The resource identity of url-kind resources is the canonical URL, version 1** (`capture/resolve.py`): `resource_key = canonical_url`, `resource_sha256 = sha256("url:" + canonical_url)`, `resource_id = sha256(canonical_url)[:8]`. Canonicalization is **conservative and versioned** (§3.1): lowercase scheme and host, default port dropped, percent-encoding normalized, a fixed list of tracking parameters removed, the fragment dropped unless it is an application route (`#!…`, `#/…`), per-host resolvers for arXiv and YouTube; the path, the query order, `www.`, trailing slashes and every unknown parameter are kept. The literal URL stays in `url:`; `canonical_url:` and `capture.canonical_version` are written on every url capture. Dedup looks up by `resource_sha256` first, then by the legacy keys of §3.1 of phase 1 **compared in canonical form**. A duplicate report (`mnemon audit --canonical`) lists existing folders that coincide under v1; nothing is merged. | #11; the vault has `utm`/`?hide_intro_popup` duplicates; aggressive normalization glues distinct pages (review). |
| D6 | **Two checks, both diagnostics, never gates.** The *acquisition check* (`check.acquisition`) classifies the fetched raw: `ok`, `js-shell` (an SPA shell: few visible words, script-heavy, an empty root element), `thin` (below `thin_words`, default 60), `blocked` (a bot wall, a login wall, a rate-limit page, a paywall teaser — by status and markers). The *conversion check* (`check.conversion`) compares the **sanitized** candidate text with the reference built from the **same raw bytes** (D7). Outcomes, recorded in `capture.completeness`: `complete` (acquisition `ok` or `thin`, no missing reference line, no table or code block lost), `partial` (missing lines, or a table/code deficit, or a `thin` landing whose rendered form is still thin), `blocked` (a paywall or login teaser was published because it was all the site served), `unknown` (no reference: text, pdf, media, legacy rendered text). A wall page is **never published**: when every stage of the chain is blocked the capture fails with `error_class: blocked`. | the program review: "completeness — диагностика, не критерий"; a gate would turn silent loss into silent refusal. |
| D7 | **The reference is the DOM text of the raw** (`convert.dom_text`): an innerText-like dump — block elements break lines, h1–h3 carry a `## ` marker, inline elements are separated by a space, nothing is dropped but `<head>`, scripts, styles, `<noscript>`, `<template>`, `<nav>`, `<footer>`, forms, cookie/consent containers and reader-comment sections; `<header>` is kept. Three candidates in order — `defuddle` (skipped for rendered raws and for a candidate with mojibake), `pandoc` from `<body>` with the same chrome removed and `<header>` kept (`-f html -t gfm-raw_html --wrap=none`), the DOM text itself — and **the first candidate that contains every reference line of ≥ 6 words wins; otherwise the DOM text**. Lines are compared by their *key*: NFKC-normalized, case-folded, soft hyphens and zero-width characters removed, **every alphanumeric character of any script kept** (letters and digits), everything else dropped. Site chrome lines (a fixed regex: cookies, ©, subscribe prompts, promo banners) and repeats of the page `<title>` are not required. Candidates and the reference are both sanitized first (D8), so the check sees the text that will be published. | the 2026-09-22 rule, rebuilt five times that day; word-count ratios failed every time. |
| D8 | **Sanitize before the check, count every repair.** HTML-level, before any converter: an SVG with `<text>` → a `<p>` placeholder with its labels, an icon SVG removed; LaTeXML `div.ltx_listingline` runs → `<pre><code>` (indentation from `ltx_lst_space`); `[⬇](data:…)` listing buttons removed. Markdown-level, after conversion: `![alt](data:image/…)` → `*[inline figure omitted at capture: alt]*`, remaining `data:` links dropped; `_next/image?url=…` → `*[img: alt]*`; `\iow_now:Ne` residue → line breaks inside a `~~~~text` fence; `[TABLE]` → a pipe table built from the matching complex table of the raw (in order; when the counts do not match, `[TABLE]` stays and is counted as unrepaired); LaTeXML macro residue before the title dropped (arXiv only); runs of blank lines collapsed. Every repair is counted in the report; `bytes_per_word` is recorded and flagged above 40, never acted on. `published:` is taken from the page only for `source_type: article`/`paper` (JSON-LD `datePublished`, `article:published_time`, arXiv `citation_date`), never for a site. | #4; the review: validate after sanitize. |
| D9 | **Site capture from a reviewable plan.** `mnemon site map <url>` discovers same-site pages (landing links, `sitemap.xml` + sitemap indexes + `robots.txt` `Sitemap:` lines, a content-verified `llms.txt`, docs tables of contents, a linked GitHub README) and writes a plan (`mnemon-site-plan/1`) with a role and an include/exclude decision per page (legal, localized copies, UI and Git how-tos, troubleshooting excluded by rule; `site_max_pages`, default 40). `mnemon add --url <landing> --site <plan.json>` (or `--site auto`: map with defaults, no review) captures every included page through the chain and the converter, assembles one composite capture-text (`## Part N — <url>` per page) and publishes one revision whose raw is a **site bundle** `<revision>.site/` (per-page raw HTML, fetch reports, the plan, a manifest with per-file hashes; `raw_sha256` = the manifest's hash) and whose frontmatter carries `folded_sources` with per-page `role`, `converter`, `completeness` and `missing_lines`; `capture.completeness` is the worst of the parts. The mapper honours `robots.txt` disallow rules, keeps ≥ 1 s between requests to one host and stops at `site_timeout`. Re-conversion of a site revision reads the bundle, never the network. The phase-1 `--depth auto` fold (thin landing → README / docs / `llms.txt`) stays as it is, on the policy of D3. | #6; "one entity = one source"; the plan is where the human decides which pages carry ideas. |
| D10 | **arXiv is a resolver, not a special origin.** `arxiv.org/abs|pdf|html/<id>[vN]` canonicalizes to `https://arxiv.org/abs/<id>`; the fetch target is `https://arxiv.org/html/<id>` (the latest LaTeXML version; 404 → the PDF at `https://arxiv.org/pdf/<id>` through the `pdf` row); `title`, `author` (joined with ", "), `published` and the version come from the abstract page's `citation_*` meta tags (a second, metadata-only request); conversion keeps only `<article class="ltx_document">` and applies the arXiv sanitize set; `source_type` defaults to `paper`; `arxiv_id` and `arxiv_version` are written. A newer version is a `--recapture` with `supersedes`. | #5; the same shape serves YouTube (`youtu.be/<id>`, `/shorts/<id>`, `watch?v=<id>&t=…` → `https://www.youtube.com/watch?v=<id>`). |
| D11 | **Stage timeouts live where the process is**: `capture-fetch.py` supervises its direct, render and external stages (`fetch_timeout`, `render_timeout`, `acquire_timeout` for the whole acquisition); `media-extract.py --timeout` supervises yt-dlp and whisper (`transcribe_timeout`); `capture-site.py` enforces `site_timeout`. Children run in their own process group and are killed with it (the `extract-run.py` pattern). A timeout is the acquisition failure class `timeout` (retryable), the receipt records the stage. The gateway sets no outer timeout, as in phase 1. | #11; a hung download held the lock. |
| D12 | **YouTube captions by the video's language.** `media-extract.py` reads the video's language from its metadata (`yt-dlp --dump-single-json`: `language`) and chooses, in order: a manual track in that language · an automatic track in it (`<lang>-orig` first) · a manual `en` or `ru` track · an automatic `en` or `ru` track · any track · whisper. The choice is a pure function over the list of available tracks (tested with fixtures). `media.json` gains `language` (the chosen track), `original_language` (from the metadata or null) and `track`; the gateway writes `transcript_language` and `original_language`. The video metadata is recorded in the receipt at acquisition, so a replay from retained whisper audio re-merges it (closes the phase-1 A7 limitation). URL audio without a usable extension is named by a content sniff after the download. | vault TODO; #11. |
| D13 | **Oversized capture-text is extracted in parts, then merged** (`extract_inline_max_bytes` unchanged, 400 000): the text is split at heading boundaries (`^#{1,3} `, else blank lines) into ≤ `extract_max_parts` (default 8) parts of at most the inline limit; each part goes through the fenced extractor with the **part template** (`templates/core/_part.md`, schema `extract-part/1`: `summary`, `key_ideas`, `quotes`); then a **merge** run with the main template receives the parts' outputs instead of the content and returns `extract/1`. `extract.md` records `extraction: chunked`, `parts: N`; the receipt records every part's cost; `extract_max_usd` caps the sum. More parts than `extract_max_parts`, or merged part outputs above the inline limit → `unsupported-size` as today. No `Read` mode. | #11, phase-1 D4; the fence does not change. |

The pending note names `mnemon add --resume`, not a retired skill. | root cause C; the review: `superseded_by` is derived, never written into the old source. |

Flat parsers keep reading top-level keys only. | #3 "record which method was used and any missing lines"; the receipt is the ledger, the frontmatter the summary a reader sees. |

## 3. The capture layer

### 3.1 Resolve — `capture/resolve.py`

`canonicalize(url: str) -> Canonical` with `Canonical(url, version=1, host_rule, dropped_params, dropped_fragment)`; `resolve(url) -> Resolution` with `Resolution(canonical, fetch_url, kind, metadata_url)` where `kind ∈ {page, arxiv, youtube, github}`.

Version 1 rules, applied in this order, nothing else:

| Step | Rule | Example |
|---|---|---|
| 1 | trim whitespace; refuse anything but `http`/`https` (exit 2 `invalid-url`); refuse userinfo | ` https://X.com ` → `https://x.com` |
| 2 | scheme and host lowercase; IDNA hosts kept as given (lowercased); default port (`:80` http, `:443` https) dropped; other ports kept | `HTTPS://Example.com:443/A` → `https://example.com/A` |
| 3 | path: percent-encoding normalized (hex uppercase, unreserved characters decoded); case, trailing slash, dot segments and everything else kept | `/a%2db` → `/a-b`; `/x/` stays `/x/` |
| 4 | query: parameters whose key is in `TRACKING_KEYS` removed — `utm_*`, `fbclid`, `gclid`, `dclid`, `gbraid`, `wbraid`, `msclkid`, `yclid`, `twclid`, `ttclid`, `igshid`, `igsh`, `mc_cid`, `mc_eid`, `_hsenc`, `_hsmi`, `hsCtaTracking`, `mkt_tok`, `_ga`, `_gl`, `ref_src`, `ref_url`, `hide_intro_popup`; on YouTube hosts also `si`, `feature`, `t`, `pp`; order of the rest preserved; an empty query dropped | `?utm_source=x&s=alpha` → `?s=alpha` (`s` kept) |
| 5 | fragment dropped unless it starts with `!` or `/` (an application route) | `#intro` dropped; `#/page-a` kept |
| 6 | per-host resolvers: arXiv `abs|pdf|html/<id>[vN]` (new and old ids) → `https://arxiv.org/abs/<id>`; YouTube `youtube.com/watch?v=<id>`, `youtu.be/<id>`, `/shorts/<id>`, `/embed/<id>`, `/live/<id>`, `m.youtube.com`, `music.youtube.com` → `https://www.youtube.com/watch?v=<id>` | `https://youtu.be/abc?si=…&t=10` → `https://www.youtube.com/watch?v=abc` |

Not done, on purpose: `www.` stripping, `http` → `https`, trailing-slash collapsing, lowercasing paths, `AMP` and mobile variants, following redirects (the redirect target is recorded as `final_url`, an alias key for dedup, never the identity). A later version bumps `version` and the dedup compares each stored folder under **the folder's own recorded version first, then the current one**.

`lib_url.normalize_url` (the depth helpers' comparison form) stays for same-site comparison only; it is no longer used for identity anywhere and says so in its docstring. `triage-urls.py` keeps its own normalizer (its dedup is advisory; phase 3 revisits it).

### 3.2 Policy — `capture/policy.py`

`Policy(user_agent, connect_timeout=15, read_timeout=45, max_bytes=20_000_000, max_redirects=5)` from the instance config (`fetch_user_agent`, `fetch_timeout` splits into connect/read, `fetch_max_bytes`); `policy.get(url) -> Response(final_url, status, headers, body: bytes, hops: [{url, status}], elapsed_ms)` or raises `PolicyError(kind)` with `kind ∈ {scheme, userinfo, ssrf-blocked, ssrf-redirect, too-many-redirects, too-large, timeout, connection, http}`. Redirects are followed by hand (`urllib.request` with a handler that raises on every `Location`), the next hop resolved and checked **before** the request; `Retry-After` on 429/503 is recorded, not waited for (the gateway's retry policy decides). No cookie jar; no `Authorization`; no credentials in URLs (`userinfo` error). Default User-Agent: a current desktop browser string (the page a reader would see); an instance may set its own.

`kb_fetch.fetch` and the probe's `fetch` become thin wrappers over `policy.get` (same return shape as today for their callers; `requests` no longer imported); `kb_fetch.defuddle_md` fetches through the policy and converts the bytes with `convert.defuddle_file`, never `defuddle parse <url>` (which fetches on its own, outside the policy).

### 3.3 Fetch — `capture/fetch.py`, `bin/capture-fetch.py`

```
capture-fetch.py <url> --out <staged raw path> --report <json> [--render | --no-render] [--no-external]
                 [--policy <json>] [--acquire-timeout S] [--render-timeout S] [--render-cmd <path>]
```

The chain (D4), with the acquisition check after every stage:

1. **direct**: `policy.get(fetch_url)` → `check.acquisition(response)` → `ok`/`thin` → done (`method: direct`, `raw_kind: response`); `paywall` with real text before the marker → done, published as `completeness: blocked` (the teaser is what the site serves; nothing escalates past a paywall); `login` → failed `blocked`/`login`, permanent, **no escalation** (content behind a login is not public); `js-shell`, `bot-wall`, `forbidden` → 2; `rate-limit` → failed `blocked`/`rate-limit`, retryable, no escalation (the chain never hammers a host that asked it to slow down); a `PolicyError` other than `http` → failed with its kind (`ssrf-blocked` is permanent; `timeout`/`connection` retryable).
2. **rendered**: `render-url.sh <url> --html --timeout <ms>` (through `RENDER_URL_CMD` when set) under `render_timeout` → `check.acquisition(rendered)` → `ok`/`thin` → done (`method: render`, `raw_kind: rendered`); `paywall`/`login` as in 1; `js-shell`/`bot-wall`/`forbidden`/empty/exit ≠ 0 → 3. Skipped with `--no-render` or without Chrome (then → 3 directly).
3. **external**: only when the instance's `external_fetch` is `auto` and `--no-external` is absent, and only for the outcomes `js-shell`, `bot-wall` and `forbidden` — never for `login`, `paywall` or `rate-limit`; each configured fetcher in order; a fetcher without a key is skipped (`skipped: no key`); the vendor's HTML is the raw (`method: firecrawl` | `jina`, `raw_kind: response`, `egress: external`); the vendor is handed `fetch_url` (which passed the policy), never a private URL; the vendor's answer goes through the acquisition check too (a vendor-relayed wall or login page is not a raw).
4. nothing left → failed: `blocked` (permanent, `retryable: false`) with the last kind (`bot-wall`/`forbidden`), or `environment` (exit 3, the gateway's existing class) when the page is a `js-shell` and no renderer exists and no external fetcher is allowed.

A PDF served without `.pdf` (content type `application/pdf` or a `%PDF-` magic) ends the chain after stage 1 with `raw_kind: file`, `content_type: application/pdf`; the gateway takes the `pdf` row as today.

The report `mnemon-fetch/1`: `{schema, url, fetch_url, canonical_url, canonical_version, kind, final_url, method, raw_kind, http_status, content_type, bytes, egress: "direct"|"external", stages: [{stage, outcome, status, bytes, elapsed_ms, note}], acquisition: {outcome, kind, evidence, visible_words}, hops: [...], elapsed_ms, error_class, error, policy: {user_agent, max_bytes, max_redirects}}`.

### 3.4 Check — `capture/check.py`

`acquisition(status, headers, body) -> Acq(outcome, kind, evidence, visible_words, title)`:

- `blocked` when (a) status 401/403/407/429/503 **or** status 200 with a tiny body, **and** a marker is present: `cf-chl`, `challenge-platform`, "Just a moment", "Attention Required", "Vercel Security Checkpoint", "Access denied", "verify you are human", `_Incapsula_`, "Please enable JavaScript and cookies", "Checking your browser", `px-captcha`, `datadome` (kind `bot-wall`); "Sign in to continue", "Log in to view", a login form as the only form and < 200 visible words (`login`); 429 or "Too many requests" (`rate-limit`); 403 without markers (`forbidden`); "Subscribe to continue reading", "This post is for paid subscribers", "Continue reading with a subscription", `class="paywall"`, `data-paywall` (`paywall` — a 200 page with real text before the marker is published as `completeness: blocked`, not refused);
- `js-shell` when visible words < 30 and (an element with `id="root"`/`id="app"`/`id="__next"`/`id="__nuxt"` is empty, or script bytes exceed 60 % of the body, or `<noscript>` says the app needs JavaScript);
- `thin` when visible words < `thin_words` (default 60) and not `js-shell`;
- `ok` otherwise.

`conversion(candidate_md, reference_lines, title) -> Conv(missing: [str], missing_count, reference_count)` per D7; `inventory(html, md) -> {headings, list_items, tables, code_blocks, links, images}` each as `{html: n, md: n}`; `outcome(acq, conv, inventory) -> complete | partial | blocked | unknown` per D6: `partial` when `missing_count > 0` or `tables.md < tables.html` or `code_blocks.md < code_blocks.html` (headings, lists, links and images are recorded, not judged — converters legitimately drop navigation).

Line keys (D7): `unicodedata.normalize("NFKC", line).casefold()`, remove U+00AD and the zero-width characters U+200B–U+200D, U+2060, U+FEFF, keep every character for which `str.isalnum()` is true. A reference line is required when its key has ≥ 6 whitespace-separated words in the original text, it is not matched by `CHROME` (cookies · "accept all" · © · "all rights reserved" · privacy/terms · subscribe/newsletter prompts · "thanks for reading" · "get the app" · "claim up to N % off"), and its key is not contained in the `<title>`'s key. A line is present when its key is a substring of the candidate's key (links reduced to their text, images removed, markup characters dropped by the key itself).

### 3.5 Convert and sanitize — `capture/convert.py`, `capture/sanitize.py`, `bin/capture-text.py`

```
capture-text.py <raw> --url <url> --out <file> --report <json> [--raw-kind response|rendered|site]
                [--kind page|arxiv] [--rendered <file>]   # --rendered: the phase-1 legacy text path, kept
```

Order of work: decode (UTF-8; a declared charset otherwise; a failure → `invalid-utf8`) → `sanitize.html(raw_html, kind)` (D8 HTML-level) → reference = `convert.dom_text(sanitized)` minus comment sections → candidates in order (`defuddle` on a temp file holding the sanitized HTML, skipped for `rendered`/`site` raws; `pandoc` on `<body>` of the sanitized HTML with chrome removed and `<header>` kept, for `arxiv` on `<article class="ltx_document">` only; the DOM text) → each candidate `sanitize.markdown(candidate, raw_html, kind)` (D8 markdown-level) → `check.conversion` on each until one passes → the winner (or the DOM text) → `check.inventory` → `check.outcome` → write `--out` (tmp + fsync + rename) and the report.

`defuddle` is run with `--markdown` on the file; its output is discarded as a candidate (`mojibake`) when it contains `â€`, `Ã©`-class sequences while the raw decodes as UTF-8 cleanly, and when it returns HTML or "Partial conversion completed with errors". An empty winner is still `error_class: convert`, exit 1 (unchanged).

The report `mnemon-capture-text/2`: the `/1` keys (`schema`, `url`, `method`, `bytes`, `words`, `title`, `completeness`, `tool`, `error_class`, `error`) plus `converter` (`defuddle` | `pandoc` | `dom-text` | `render-text`), `candidates: [{converter, missing_count, chosen: bool, note}]`, `reference_count`, `missing_count`, `missing_examples` (≤ 5, each ≤ 120 characters), `inventory`, `repairs: {data_uris, data_links, svg_diagrams, svg_icons, next_images, table_placeholders, tables_repaired, tables_unrepaired, latexml_listings, tcolorbox_residue, residue_lines, comment_sections}`, `bytes_per_word`, `bloat: bool`, `published` (date or null), `authors` (arXiv), `arxiv_id`, `arxiv_version`, `tools: {defuddle, pandoc}` versions. `method` keeps the phase-1 form `<fetch>+<converter>` (`direct+defuddle`, `render+pandoc`, `firecrawl+dom-text`, `site+mixed`); the gateway composes it from the two reports.

### 3.6 Site — `capture/site.py`, `bin/capture-site.py`, `mnemon site`

```
mnemon [--instance I] site map <url> [--max-pages N] [--include <regex>]… [--exclude <regex>]… [--out <plan.json>] [--json]
capture-site.py map <url> … ; capture-site.py assemble <bundle dir> --out <capture.md> --report <json>
mnemon add --url <landing> --site <plan.json | auto> [other add flags]
```

Discovery sources, each recorded with what it yielded: the landing page's same-site links (after rendering when the landing is `js-shell`); `/sitemap.xml` and every `Sitemap:` of `/robots.txt`, sitemap indexes followed one level; `/llms.txt` when it is text and not the landing shell (the phase-1 probe's check); docs tables of contents (`HelpTOC.json` of Writerside; links under the first `/docs` page); a GitHub repository linked from the landing (its README, as the depth fold does). Same site = `lib_url.same_site`; `docs.<domain>` counts. `robots.txt` `Disallow` rules for `*` and for the configured agent exclude pages (recorded as `excluded: robots`).

Roles by path and title rules, in this order: `legal` (`/privacy`, `/terms`, `/legal`, `/cookie`, `/imprint`, `/eula`, `/gdpr`) · `localized` (a path or subdomain starting with a locale tag such as `/de-de/`, `/fr/`, `ja.` — excluded) · `howto` (`/troubleshooting`, `/faq`, `/changelog`, `/release-notes`, titles starting with "How to", "Install", "Getting started with Git") · `blog` (`/blog/`, `/posts/`, `/news/`) · `docs` (`/docs`, `/help`, `/guide`, `/manual`, `/reference`) · `pricing` · `careers` (`/careers`, `/jobs`) · `job` (`/jobs/<id>`, `/careers/<slug>`) · `product` (every other same-site page one or two segments deep) · `other`. Included by default: `landing`, `product`, `docs`, `blog`, `pricing`, `careers`, `job`; excluded: `legal`, `localized`, `howto`, `other`. `--include`/`--exclude` regexes apply after the rules. The plan is capped at `site_max_pages` (default 40) by role priority (landing → product → docs → pricing → blog → careers → job), the rest listed as `excluded: cap`.

The plan `mnemon-site-plan/1`: `{schema, landing, created, discovery: {sources: [...], robots: [...]}, pages: [{url, canonical_url, role, include, reason, title, discovered_by, render: bool|null}], caps: {max_pages}}` — editable by hand before `mnemon add --site`. `--site auto` writes the plan into the attempt dir and goes on.

Acquisition of a site revision (the gateway's `cap_acquire_site`): the bundle is staged as `<raw dir>/.<revision>.site.staging-<pid>/`; for each included page in plan order `capture-fetch.py` writes `NN.html` + `NN.fetch.json` (≥ 1 s between requests to the same host, `site_timeout` overall; a page that fails is recorded in the manifest with its error and **skipped**, never fatal — a site with one dead page is still a site; the landing failing is fatal); `plan.json` and `manifest.json` (`{schema: "mnemon-site-bundle/1", pages: [{n, url, file, sha256, bytes, fetch: {method, status}}], created}`) are written last; `raw_sha256` = sha256 of the manifest's canonical JSON, `raw_bytes` = the sum of the files; the staged directory is renamed into place (one rename) and recorded like any raw. Then `capture-site.py assemble <bundle> --out capture.md --report` converts every page (`capture-text.py` logic in-process, `raw_kind: site`), writes the composite:

```
# <landing title> — site capture

## Part 1 — <landing url>

<page text>

## Part 2 — <url> (<role>)

<page text>
```

and the report `mnemon-site/1` (`{schema, pages: [{n, url, role, converter, completeness, missing_count, words, bytes, skipped: reason|null}], completeness, words, bytes}`). The gateway writes `folded_sources:` (one entry per part after the first: `url`, `role`, `converter`, `completeness`, `missing_lines`), `site_pages: N`, `capture.raw_kind: site`, `capture.completeness` = worst of the parts, `method: site+mixed` (or `site+pandoc` when one converter served every part). `cap_reconvert` for `raw_kind: site` runs `assemble` on the retained bundle.

Depth-aware fold (`--depth auto`) is unchanged in behaviour; `kb-depth-fold.py` fetches through the policy (§3.2).

### 3.7 Media — `bin/media-extract.py`

- `--timeout <s>` (default from `transcribe_timeout`, 3600): yt-dlp, ffprobe and whisper run in their own process group under this budget; a timeout exits 124 with `error_class: timeout` in `media.json`'s place (`error.json`), nothing under `--out-dir` is deleted.
- Track choice (D12): `choose_track(tracks, original_language) -> Track` where `tracks = [{lang, kind: manual|auto, orig: bool}]` from the transcript API's listing and `original_language` from `yt-dlp --dump-single-json` (`language`, else null). Order: manual in `original_language` · auto `<original_language>-orig` · auto in `original_language` · manual `en` · manual `ru` · auto `en` · auto `ru` · the first manual · the first auto · whisper. Pure, tested with a fixture list (`tests/fixtures/capture/tracks.json`: a Portuguese video with manual pt and auto en, an English video with auto en-orig only, a video with no tracks).
- `media.json` (`mnemon-media/1`, additive): `language`, `original_language`, `track` (`{lang, kind, orig}` or null), `metadata: {title, duration, upload_date, video_id, channel}`; `method` unchanged.
- The gateway records `media_meta` in the receipt at acquisition; `cap_media_meta` falls back to it when `media.json` of a re-transcription lacks the keys (replay from whisper audio).
- URL audio: after the download the gateway sniffs the type (`file -b --mime-type`; `audio/mpeg → mp3`, `audio/mp4 | audio/x-m4a → m4a`, `audio/x-wav | audio/wav → wav`, `audio/ogg → ogg`, `audio/flac → flac`, `audio/aac → aac`, `video/mp4 → mp4`, `video/webm | audio/webm → webm`) and renames the staged file before the raw is committed; the URL's extension is the fallback, `bin` the last resort (`.audio` is never written again; existing `.audio` raws stay readable).

### 3.8 Chunked extraction (D13) — `bin/lib-capture.sh`, `bin/extract-publish.py`, templates

`cap_extract`: when `text_bytes > EXTRACT_INLINE_MAX_BYTES`: `extract-publish.py split --in capture.md --max-bytes N --max-parts M --out-dir <attempt>/parts/` writes `part-<n>.md` (split at `^#{1,3} ` boundaries, else at blank lines; a single paragraph above the limit → `unsupported-size`) and `parts.json`; for each part: prompt = the §4.5 prompt with `=== CONTENT ===` = the part, `=== EXTRACTION TEMPLATE ===` = `templates/core/_part.md`, schema `extract-part/1` (`extract-publish.py schema --part`: `summary` (≤ 1 500 chars), `key_ideas` (array of `{claim ≤ 200, domain}`, ≤ 20), `quotes` (array of strings, ≤ 8)); validated with the same rules; results in `parts/part-<n>.json`. Then the merge: prompt as §4.5 with `=== CONTENT ===` replaced by `=== PART EXTRACTS (N) ===` holding the parts' outputs rendered as markdown, the main template, schema `extract/1`; validated and published as today. `extract.md` frontmatter gains `extraction: chunked`, `parts: N` (`extraction: single` otherwise); the receipt gets `parts: [{n, bytes, cost_usd, duration_ms}]`, `cost_usd` = the sum; `--dry-run` prints the plan (parts and sizes). A part failure fails the capture as `extract-failed` with the part's class; `--resume` re-runs every part (no part cache in phase 2 — stated).

### 3.9 Index — `bin/knowledge-reindex.py` (D14)

- Every row is generated; `index_note` from `extract.md` is appended as ` — <note>`; derived `superseded` from a scan of every `source.md`'s `supersedes:` (a map new → old; both forms); a superseded row gets ` ⤳ superseded by [[Sources/<new>/extract|<new title>]]` and the counter line reports `N superseded`.
- The first run that would change a row that existed (its text differs from the regenerated one and is not explained by `index_note`/derived status) writes the old rows to `<vault>/_inputs/index-hand-edits-<date>.md` (created once; appended on later runs only for rows not already listed) and prints a one-line notice.
- The pending note: `_N source(s) captured without extract.md (finish with `mnemon add --resume <revision>`)._`; a `status: bookmark`/`fetch_status: failed` legacy folder is counted apart (`N legacy placeholders`).
- `mnemon status` reports `superseded` and `chunked` counts (reads `extract.md` keys).
