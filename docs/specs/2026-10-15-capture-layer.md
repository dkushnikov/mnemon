# Capture layer — resolve · fetch · convert · sanitize · check · site; canonical identity; media language; index regeneration; stage timeouts (phase 2)

**Status:** v2.1 — v2 accepted by the second external review with the binding amendments of §12 · **Program:** capture overhaul, phase 2 · **Builds on:** `docs/specs/2026-10-15-capture-contracts.md` v4.1 (phase 1; its contracts are not changed by this document, only extended where it says "phase 2") · **Closes:** #3, #4, #5, #6 and the phase-2 items of #11.

## Resume prompt

Phase 1 made the gateway honest about *what* it published (three artifacts, three hashes, receipts, a kernel-held lock, a fenced extractor). It did nothing about *whether what it published is the page*: `completeness: unknown` on every capture, one converter chain (`defuddle` → `pandoc`) that silently drops sections, arXiv from the abstract page, no multi-page capture, identity by the literal URL, YouTube captions in the wrong language, index rows frozen forever. This spec adds the capture layer underneath the phase-1 contracts: a python package `bin/capture/` with one network policy for the engine's own requests (and a stated, narrower boundary for the browser and the media tools), a fetch chain (direct → rendered → external, the last only when the instance allows it and never past a login, a paywall or a rate limit), a three-way converter with a **diagnostic** completeness check against the saved raw, a sanitizer, site (multi-page) capture from a reviewable plan into a hashed bundle, per-host resolvers (arXiv full text with pinned versions, YouTube), a conservative versioned canonicalization that becomes the identity of **new** url resources under a versioned request schema, stage timeouts with named owners, chunked extraction with one budget, language-aware YouTube captions, and an index whose rows are regenerated from files behind a preservation step.

## 2. Decisions

| # | Decision | Why |
|---|---|---|
| D1 | **The capture layer is a python package `bin/capture/`** (stdlib only, python 3.9): `policy.py` (network policy), `fetch.py` (fetch chain), `resolve.py` (canonicalization + per-host resolvers), `convert.py` (three-way conversion), `sanitize.py`, `check.py` (acquisition and conversion checks, inventory), `site.py` (map · fetch-bundle · assemble), `report.py` (schemas), `lib_table.py` (merged-cell tables → simple tables). Three CLIs the gateway calls: `bin/capture-fetch.py` (URL → raw file + fetch report), `bin/capture-text.py` (raw + fetch report → capture-text + report; the phase-1 name and flags kept, schema v2), `bin/capture-site.py` (map · fetch-bundle · assemble). The gateway stays the orchestrator and the only writer of `source.md`. | bash cannot do DOM parsing or unicode alignment; one package keeps the modules on one policy and one report. |
| D2 | **Acquire and convert stay two gateway steps.** `capture-fetch.py` writes the raw to the staged path the gateway names and never converts; `capture-text.py` converts a retained raw and never fetches. What only the fetch could see (status, classification, charset, egress, resolver metadata) travels to the converter **through the fetch report**, which the gateway records in the receipt before the raw is published, so an offline reconversion has the same inputs as the first. The phase-1 recovery rows hold unchanged: a conversion failure re-converts the retained raw, never refetches. | §3.4 of phase 1; "a converted page without its HTML cannot be verified or redone" (D8 of phase 1); the review: the converter cannot reconstruct acquisition facts from bytes. |
| D3 | **One network policy for every request the engine's own code makes** (`capture/policy.py`): the direct fetch, the site mapper and bundle fetcher, the depth helpers (`kb_fetch.py`, `kb-probe-deeper.py`, rewritten over the policy; `requests` dropped), the arXiv metadata fetch, URL audio and URL PDF downloads (both move from `curl` in the gateway to `capture-fetch.py --expect pdf|audio`), and the target URL handed to an external fetcher. The policy: `http`/`https` only; no userinfo; **every hop's host is resolved, every returned address checked** (private, loopback, link-local, reserved, multicast, unspecified → `ssrf-blocked`/`ssrf-redirect`), and **the connection is pinned to a checked address** (TLS verified against the host name, SNI and `Host` = the host) so a rebinding answer cannot redirect it; at most 5 redirects, each re-checked before it is followed; a byte cap (`fetch_max_bytes`, default 20 MB, measured on the decoded body as received; a capped download is `too-large`, never a truncated raw); connect/read timeouts; one User-Agent (`fetch_user_agent`); **no proxies** (`http.client` directly, never `urllib`'s ambient `ProxyHandler`; a proxy option is a non-goal); no cookies, no `Authorization`, no credentials. **Two boundaries the policy does not reach are named, not pretended:** (1) the **renderer** (`render-url.sh`, headless Chrome) — the policy checks the URL before Chrome launches (the first hop), Chrome runs with a throw-away profile and a mock keychain (no stored cookies or credentials; anonymous cookies it creates during one render die with the profile), a virtual-time budget, a wall-clock timeout and an output cap (`render_max_bytes`); **browser and vendor target fetching are outside connection pinning, redirect enforcement and download-volume guarantees** — the URL check before Chrome launches is a pre-validation of the name, not first-hop enforcement; Chrome's own connection, redirects, subresources and script-initiated requests are not policed, `render_max_bytes` limits only the returned DOM output, and `capture.fetch: render` says so; (2) the **media tools** (`yt-dlp`, `youtube_transcript_api`, `whisper`) — the policy checks the video URL's host (YouTube hosts only for `youtube`; the policy's checks for URL audio) before they run; their own requests are theirs, under the media timeout. Vendor APIs (Firecrawl, Jina) are authenticated requests to fixed public endpoints; the policy validates the *target* URL, the endpoint is trusted by configuration. | the review: wrapping a browser in a timeout is not a network boundary; pinning defeats DNS rebinding; ambient proxies are a leak. |
| D4 | **The fetch chain is direct → rendered → external, and the raw of a rendered page is its post-JS HTML.** Direct = the policy's GET. Rendered = `render-url.sh --html` when the direct result is classified `js-shell`, `thin`, `bot-wall` or `forbidden` (one decision table, §3.4), or on `--render`; the raw is the rendered DOM HTML (`<revision>.html`, `raw_kind: rendered`; no HTTP status or final URL is known for it and both are recorded as `null`, never invented). External = Firecrawl or Jina Reader, in the order of `external_fetchers`, **only** when the instance says `external_fetch: auto` (default `off`), only for `js-shell`, `bot-wall` and `forbidden` after direct and rendered both failed, only for a URL that passes the policy, with keys from the environment (`FIRECRAWL_API_KEY`, `JINA_API_KEY`); a fetcher without a key is skipped with a note; a vendor's answer is classified like any other and a relayed wall is not a raw. **Nothing in the chain is a way past a login, a paywall or a rate limit**: a login wall fails the capture (permanent), a paywall teaser with real text is published as `completeness: blocked`, a 429 fails as retryable and is retried later by the ingest's own backoff, never by the chain. The chain records every stage it tried. | program D7; the Vercel checkpoint passed in headless Chrome, not in curl; the review: one decision table, nothing invented for rendered pages. |
| D5 | **Canonical identity, version 1, under a versioned request schema.** New url-kind captures write `mnemon-request/2`: `resource_key = canonical_url` (§3.1), `resource_sha256 = sha256("url:" + canonical_url)`, `resource_id = sha256(canonical_url)[:8]`, plus the bound fields `canonical_version`, `render` (`auto`/`force`/`off`), `external` (`auto`/`off`), `site` (`null`, `"auto"`, or the plan's `input_sha256`), `requested_version` (arXiv). **A replay never re-derives identity**: `cap_restore_from_receipt` restores `resource_key`, `resource_sha256`, `resource_id` and the request schema from the receipt, and the binding check compares the given arguments against the stored request *as its own schema encodes them* (`/1`: the literal URL, no new fields; `/2`: canonical v1). Canonicalization is **conservative and versioned** (§3.1). The literal URL stays in `url:`; `canonical_url:` and `capture.canonical_version` are written on every new url capture; `canonical_url` is **reserved for computed identity** — the page-declared `<link rel=canonical>` that the depth probe used to write there moves to `declared_canonical_url`. Lookups (§4.1) collect every folder whose identity, old or new, canonicalizes to the same v1 string, then choose the head deterministically; **a folder that carries `resource_sha256` is a managed phase-1 folder whatever its label and goes through the managed path** (resume when incomplete, verified dedup when complete); only folders without it are `legacy_match: true`. A duplicate report (`mnemon audit --canonical`) lists existing folders that coincide under v1; nothing is merged. | #11; the review: `cap_binding_check` recomputes identity, so a `/1` receipt replayed under v1 rules would exit 2; the legacy branch skipped incomplete folders. |
| D6 | **Two checks, both diagnostics; refusals are acquisition decisions, not completeness.** The *acquisition classification* (`check.acquisition`, one ordered decision table in §3.4) names what the fetched raw is — `ok`, `thin`, `js-shell`, `bot-wall`, `forbidden`, `login`, `paywall`, `rate-limit`, `not-found`, `server-error`, `unavailable` — and the chain decides from it whether to stop, escalate or fail. The *conversion check* (`check.conversion`) compares the sanitized candidate with the reference projected from the **same raw bytes** (D7). `capture.completeness` is defined **relative to the saved snapshot**: `complete` = every eligible reference line present with its word boundaries, every heading present, no table or code block lost; `partial` = otherwise; `blocked` = a paywall teaser was published (the text before the wall); `unknown` = no reference (text, pdf, media, legacy rendered text, a reference with zero eligible lines). The acquisition classification is recorded beside it (`capture.acquisition`), so "complete" never claims the fetch got the intended page — only that the conversion kept what the fetch got. A wall page is **never published** — the one exception is the labelled paywall teaser (row 11 of §3.4: real text before the wall, `completeness: blocked`); when every stage ends on a wall the capture fails with `error_class: blocked`. | the program review: "completeness — диагностика, не критерий"; the v1 review: the DOM fallback trivially matches its own reference, so the two halves must be reported apart. |
| D7 | **The reference is the DOM text of the raw's content subtree, and one pipeline projects reference, candidates and inventory.** `sanitize.html` runs first on the raw (D8); the content subtree is `<article class="ltx_document">` for arXiv, else `<body>`, with `<head>`, scripts, styles, `<noscript>`, `<template>`, `<nav>`, `<footer>`, forms, cookie/consent containers and reader-comment sections removed and `<header>` kept; the **reference** = `convert.dom_text(subtree)` (block elements break lines, h1–h3 carry `## `, inline elements are separated by a space, nothing else dropped); the **candidates**, in order — `defuddle` (on the sanitized HTML; skipped for rendered, site and external raws and for a candidate with mojibake), `pandoc` on the same subtree (`-f html -t gfm-raw_html-tex_math_dollars --wrap=none`; `tex_math_dollars` off so the `$…$` text of D8 passes as text, never escaped), the DOM text itself — each run through `sanitize.markdown` (D8); the **inventory** counts the same subtree. **The first candidate that contains every eligible reference line and every heading wins; otherwise the DOM text** (which satisfies the reference by construction; `converter: dom-text` and the inventory say what was lost). Presence is two-level: the *key* (NFKC, casefold, soft hyphens and zero-width characters removed, every alphanumeric character of any script kept) must be a substring of the candidate's key, **and** the line's *word sequence* (the alphanumeric tokens in order) must occur as a contiguous token sequence in the candidate's tokens — a key match without the token match is a **glued** line (counted apart, treated as missing). Eligible lines: ≥ 6 whitespace-separated words, or ≥ 20 characters of scripts written without spaces (CJK, Thai; the token check is skipped for them); not a chrome line (`CHROME` regex, applied only to lines of ≤ 12 words); not equal to the `<title>`'s key. Every h1–h3 heading of the reference (≥ 2 words) is required regardless of length. | the 2026-09-22 rule, rebuilt five times that day; the v1 review: alphanumeric keys made "Deploythecompanybrain" equal to "Deploy the company brain" (reproduced). |
| D8 | **Sanitize before the check, count every repair, never guess a position.** HTML-level, before the reference and the converters: every `<math>` element → the text node `$<alttext>$` (display math `$$…$$`; without `alttext` the `<annotation encoding="application/x-tex">` text, without either the element's visible text — counted as `math_sources`), so the reference, every candidate and the published text carry the formula's source and never the glyphs glued to it (`θ\theta`); an SVG with `<text>` → a `<p>` placeholder with its labels, an icon SVG removed; LaTeXML `div.ltx_listingline` runs → `<pre><code>` (indentation from `ltx_lst_space`); `[⬇](data:…)` listing buttons removed; **merged-cell tables rewritten into simple tables** (cells duplicated across their span, stacked header rows joined with " · ") so pandoc never emits `[TABLE]` for them — the nth-placeholder guesswork is gone; a `[TABLE]` pandoc still emits stays and is counted as `tables_unrepaired`. Markdown-level, after conversion, **fence-aware** (nothing inside ``` or ~~~ fences is touched): `![alt](data:image/…)` → `*[inline figure omitted at capture: alt]*`, remaining `data:` links dropped; `_next/image?url=…` → `*[img: alt]*`; `\iow_now:Ne` residue → line breaks inside a `~~~~text` fence; LaTeXML macro residue before the title dropped (arXiv only); runs of blank lines collapsed. Both levels are idempotent (a second pass changes nothing; tested). Repairs are counted per candidate; the report carries the chosen candidate's counts and the HTML-level counts. `bytes_per_word` is recorded and flagged above 40, never acted on. `published:` is the **gateway's** decision from the converter's dated candidates (§3.5): for `source_type: paper` the arXiv `citation_date`, for `article` an `article:published_time` or the `datePublished` of a JSON-LD node of type `Article`/`BlogPosting`/`NewsArticle`/`ScholarlyArticle`, never a `WebSite`/`Organization`/`Product` node, never for a site. | #4; the review: equal counts do not prove the nth table is the nth placeholder; fence-unaware regexes corrupt code. |
| D9 | **Site capture from a reviewable plan into a hashed bundle.** `mnemon site map <url>` discovers same-site pages and writes a plan (`mnemon-site-plan/1`) with a role, an include/exclude decision and a reason per page (§3.6); `mnemon add --url <landing> --site <plan.json>` (or `--site auto`) is an acquisition mode of the **landing resource**: the plan is the capture's input (`input_path`, `input_sha256`, the phase-1 locator mechanism; `auto` writes the generated plan to `attempt-1/plan.json` and it is the locator from then on), the revision's raw is a **bundle directory** `<revision>.site/` whose manifest names every member with path, size and hash, every included page gets a **disposition** (`captured`, `fetch-failed`, `convert-failed`, `skipped-timeout`, `excluded`) that stays visible in the manifest, the report and `folded_sources`, and the aggregate completeness is `complete` only when every included page is captured complete. `capture-site.py fetch-bundle` owns the page loop and its deadline; the gateway stages, hashes, records and renames the directory exactly as it does a file (§4.3). A landing with an existing revision needs `--recapture` for a site capture (the new revision `supersedes` the plain one). The mapper honours `robots.txt` (group precedence and `Allow` as RFC 9309 defines them; a plan cannot override a `Disallow`), keeps ≥ 1 s between requests to one host, and admits only hosts of §3.6's eligibility rule (no public-suffix guessing). The phase-1 `--depth auto` fold is re-sequenced behind the chain (§4.2), not left in front of it. | #6; "one entity = one source"; the review: a bundle must bind all its evidence; a site with one captured page is not complete; depth preflight bypassed the chain. |
| D10 | **arXiv is a resolver with pinned versions.** `arxiv.org/abs|pdf|html/<id>[vN]` canonicalizes to `https://arxiv.org/abs/<id>` (the paper is the resource); `requested_version` = N from the URL or `null`; the fetch **resolves the version once** — the abstract page of the requested version (or the latest) gives `citation_*` metadata and the version number, and the content is fetched for **that** version (`html/<id>vN`, else `pdf/<id>vN` through the `pdf` row); `arxiv_version` (fetched) and `arxiv_requested_version` are written; conversion keeps `<article class="ltx_document">` and applies the arXiv sanitize set; `source_type` defaults to `paper`. A later version is a `--recapture` with `supersedes`; a request for another version of a captured paper without `--recapture` is `skipped-duplicate` naming the captured version. | #5; the review: an explicit v1 URL must not archive v3. |
| D11 | **Every deadline has one owner, children run in their own process group, budgets are passed down.** `capture-fetch.py` owns the whole acquisition of one URL (`acquire_timeout`): the direct stage (`fetch_timeout`), the render stage (`render_timeout`), the external stage; `capture-site.py` owns mapping (`site_timeout`) and the bundle loop (`site_timeout` for the loop, `fetch_timeout` per page; the remaining budget is passed to each page fetch); `media-extract.py` owns `transcribe_timeout` for yt-dlp, ffprobe, whisper **and the caption fetch** (run as its own subprocess, `media-extract.py _captions`, so a hung HTTP call in a library is killable); the depth fold runs under the acquisition's remaining budget (`--budget-s`). Every owner spawns children with `start_new_session=True`, kills the group on expiry, reaps it, and exits 124 with `error_class: timeout` and `stage` in its report; the gateway maps 124 → `FAIL_CLASS=timeout` (retryable), closes nothing it did not open, and holds no outer timeout, as phase 1 requires. The vault-lock descriptor is closed in every capture-layer child (they never write into the vault). | #11; the review: the loop in bash had no deadline owner; the transcript API was outside supervision. |
| D12 | **YouTube captions by the video's language.** `media-extract.py` reads `language` from `yt-dlp --dump-single-json` and chooses, in order: a manual track in that language · an automatic track in it (`<lang>-orig` first) · a manual `en` or `ru` track · an automatic `en` or `ru` track · the first manual · the first automatic · whisper (a pure, fixture-tested function). `media.json` keeps its top-level keys (`method`, `audio_path`, `title`, `duration`, `upload_date`, `video_id`) and adds top-level `language`, `original_language`, `track`, `channel`. The gateway records `media_meta` in the receipt at acquisition; on a replay from retained whisper audio the receipt is **authoritative** for `video_title`, `upload_date`, `duration`, `video_id` (a transcription-only run reports only what it can know). URL audio without a usable extension is named by a content sniff after the download. | vault TODO; #11; the review: a nested `metadata` object broke existing consumers; a filename-derived title is not "missing". |
| D13 | **Oversized capture-text is extracted in parts, then merged, under one budget for the capture's lifetime.** The text is split at heading boundaries outside fences (`^#{1,3} `, else blank lines) into ≤ `extract_max_parts` (default 8) parts of at most `extract_inline_max_bytes`; each part goes through the fenced extractor with the part template (`templates/core/_part.md`, schema `extract-part/1`, §3.8); the merge run receives the parts' outputs instead of the content and returns `extract/1`. Every billable call (parts, merge, validation retries, failed calls that returned a cost) is debited from `extract_max_usd`; each call receives `--max-budget-usd` = the remaining budget; the receipt records every call; `extract.md` records `extraction: chunked`, `parts: N`. More parts than allowed, a single paragraph above the limit, or merge inputs above the inline limit → `unsupported-size`. No `Read` mode, no part cache (a resume re-runs the parts and keeps debiting the same budget). | #11, phase-1 D4; the review: a per-call budget exceeds the promised total. |
| D14 | **Index rows are regenerated from files behind a preservation step; hand-edits move to frontmatter.** `knowledge-reindex.py` rebuilds every row; `index_note:` in `extract.md` is appended; `superseded` is **derived** from every `source.md`'s `supersedes:` and marked on the old row; nothing is written into any `source.md` or `extract.md`. ## 3. The capture layer

### 3.1 Resolve — `capture/resolve.py`

`canonicalize(url: str, version: int = 1) -> Canonical` with `Canonical(url, version, host_rule, dropped_params, dropped_fragment)`; `resolve(url, version=1) -> Resolution` with `Resolution(canonical, fetch_url, kind, metadata_url, requested_version)` where `kind ∈ {page, arxiv, youtube, github}`. `version` selects a frozen rule set; v1 is the only one now; a later version adds rules and keeps v1 callable (lookups compare under a folder's recorded version first, then the current one).

Version 1 rules, applied in this order, nothing else:

| Step | Rule | Example |
|---|---|---|
| 1 | trim whitespace; refuse anything but `http`/`https` (`invalid-url`); refuse userinfo; refuse a malformed port or percent-escape (`invalid-url`) | ` https://X.com ` → `https://x.com` |
| 2 | scheme and host lowercase; IDNA hosts kept as given (lowercased); default port (`:80` http, `:443` https) dropped; other ports kept | `HTTPS://Example.com:443/A` → `https://example.com/A` |
| 3 | path: percent-encoding normalized (hex uppercase, unreserved characters decoded, reserved ones left encoded); case, trailing slash, dot segments and everything else kept | `/a%2db` → `/a-b`; `/x/` stays `/x/` |
| 4 | query: split on `&`; keys and values percent-decoded for *matching* only; parameters whose decoded key is in `TRACKING_KEYS` removed — `utm_*`, `fbclid`, `gclid`, `dclid`, `gbraid`, `wbraid`, `msclkid`, `yclid`, `twclid`, `ttclid`, `igshid`, `igsh`, `mc_cid`, `mc_eid`, `_hsenc`, `_hsmi`, `hsCtaTracking`, `mkt_tok`, `_ga`, `_gl`, `ref_src`, `ref_url`, `hide_intro_popup`; duplicates, bare keys and empty values kept as written; order preserved; an empty query dropped | `?utm_source=x&s=alpha&a` → `?s=alpha&a` |
| 5 | fragment dropped unless it starts with `!` or `/` (an application route) | `#intro` dropped; `#/page-a` kept |
| 6 | per-host resolvers, applied to the result of 1–5: arXiv `abs|pdf|html/<id>[vN]` (new and old ids) → `https://arxiv.org/abs/<id>`, `requested_version` = N or null; YouTube `youtube.com/watch?v=<id>…`, `youtu.be/<id>`, `/shorts/<id>`, `/embed/<id>`, `/live/<id>`, `m.youtube.com`, `music.youtube.com` → `https://www.youtube.com/watch?v=<id>` (navigation context `list`, `index`, `t`, `si`, `feature`, `pp` dropped — the video is the resource) | `https://youtu.be/abc?si=…&t=10` → `https://www.youtube.com/watch?v=abc` |

Not done, on purpose: `www.` stripping, `http` → `https`, trailing-slash collapsing, lowercasing paths, AMP and mobile variants, following redirects (the redirect target is recorded as `final_url`, an alias key for lookups, never the identity), GitHub path rewriting.

`lib_url.normalize_url` stays for the depth helpers' same-site comparison only and says so in its docstring; `triage-urls.py` keeps its own normalizer (advisory dedup; phase 3).

`capture-fetch.py --canonical-only <url>` prints one JSON object and exits 0: `{"schema":"mnemon-canonical/1","url":"<as given, trimmed>","canonical_url":"…","canonical_version":1,"kind":"page|arxiv|youtube|github","fetch_url":"…","requested_version":null|N}`; exit 2 with `{"error_class":"invalid-url","error":"…"}` on stderr otherwise. `--canonical-only --stdin` reads one URL per line and prints one such object per line (an invalid line prints an object with `error_class` and the run still exits 0) — the gateway's lookup canonicalizes every candidate folder's URLs in one call. No network.

### 3.2 Policy — `capture/policy.py`

`Policy(user_agent, connect_timeout, read_timeout, max_bytes, max_redirects=5)` from the instance config (`fetch_user_agent`; `fetch_timeout` T → connect = min(15, T/4), read = T − connect; `fetch_max_bytes`); `policy.get(url, *, deadline=None) -> Response(final_url, status, headers, body: bytes, hops: [{url, status, address}], elapsed_ms)` or raises `PolicyError(kind)` with `kind ∈ {scheme, userinfo, invalid-url, ssrf-blocked, ssrf-redirect, too-many-redirects, too-large, timeout, connection, tls}`; an HTTP error status is **not** an exception — the response is returned with its status and body for classification (§3.4). Mechanics: the host is resolved (`getaddrinfo`); **every** returned address is checked; the connection is made to the first address (`http.client.HTTPConnection`/`HTTPSConnection` subclasses whose `connect()` opens the socket to the checked address and wraps it with `ssl.create_default_context()` and `server_hostname=host`; the `Host` header is the host name); a `Location` is resolved relative to the current URL, re-checked (steps above), and followed only then; `Retry-After` is recorded in the response, never waited for; the body is read in chunks with the cap applied to the decoded bytes (gzip/deflate handled by the engine when it sent `Accept-Encoding`; a `Content-Length` above the cap stops before any body is read); no `Cookie`, no `Authorization`, no proxy of any kind. A redirect to a `data:`/`file:`/`ftp:` URL is `scheme`.

Test hooks, honoured only when `MNEMON_TEST_HOOKS=1` is set (the phase-1 convention for crash injection): `MNEMON_POLICY_ALLOW_LOOPBACK=1` lets a local test server on `127.0.0.1`/`::1` be fetched; `MNEMON_FETCH_URL_REWRITE="https://arxiv.org=http://127.0.0.1:PORT;https://www.youtube.com=…"` rewrites the prefix of a fetch URL before the request (the canonical URL and the identity are untouched); `MNEMON_EXTERNAL_FETCH_CMD=<command>` replaces the vendor HTTP calls (`<command> <fetcher> <url>`, stdout = the vendor's HTML, exit ≠ 0 = that fetcher failed). Without `MNEMON_TEST_HOOKS=1` the three variables are ignored and a warning names them (tested).

`kb_fetch.fetch` and the probe's `fetch` become thin wrappers over `policy.get` (same return shape for their callers); `kb_fetch.defuddle_md` fetches through the policy and converts the bytes with `convert.defuddle_file`, never `defuddle parse <url>`.

### 3.3 Fetch — `capture/fetch.py`, `bin/capture-fetch.py`

```
capture-fetch.py <url> --out <staged raw path> --report <json> [--expect page|pdf|audio] [--render | --no-render]
                 [--no-external] [--policy <json>] [--acquire-timeout S] [--render-timeout S] [--render-cmd <path>]
                 [--external <json: {"mode":"off|auto","fetchers":["firecrawl","jina"]}>]
capture-fetch.py --canonical-only <url>
```

`--expect pdf|audio` (URL PDF and URL audio, replacing the gateway's `curl`): one direct policy GET, no classification beyond status (a non-2xx fails with the status class), a PDF without the `%PDF-` magic fails `not-pdf`, the audio file's type is sniffed (§3.7). `--expect page` (default) runs the chain:

1. **direct**: `policy.get(fetch_url)` (for `kind: arxiv` first the metadata request, §3.5) → the decision table (§3.4) → `ok`/`thin`¹ → done (`method: direct`, `raw_kind: response`); `paywall` → done, published as `completeness: blocked`; `login`, `rate-limit`, `not-found`, `server-error`, `unavailable`, `too-large`, `ssrf-*` → failed with that class and the table's `retryable`; `js-shell`, `bot-wall`, `forbidden` (and `thin`¹) → 2.
2. **rendered** (skipped with `--no-render`, or without Chrome → 3): `render-url.sh <url> --html --timeout <ms> --max-bytes <render_max_bytes>` under `render_timeout` → the table on the rendered HTML (status and final URL `null`) → `ok`/`thin` → done (`method: render`, `raw_kind: rendered`)¹; `paywall`/`login` as in 1; `js-shell`/`bot-wall`/`forbidden`/empty/exit ≠ 0 → 3.
3. **external** (only `external.mode == auto`, no `--no-external`, and only for `js-shell`, `bot-wall`, `forbidden`): each fetcher in order; without a key → `skipped: no key`; the vendor's HTML goes through the table (a relayed wall or login is not a raw); `ok`/`thin` → done (`method: firecrawl|jina`, `raw_kind: response`, `egress: external`).
4. nothing left → failed: `blocked` with the last kind (`bot-wall`/`forbidden`, permanent) or `environment` (exit 3 at the gateway: a `js-shell` with no renderer and no external fetcher allowed).

¹ `thin` is not a failure: a thin direct page is rendered once; the richer of the two (more visible words) is kept and the other is recorded in `stages`; a page that stays thin is published with `acquisition: thin` and its completeness judged like any other.

A PDF served as a page (content type `application/pdf` or the `%PDF-` magic) ends the chain after stage 1 with `raw_kind: file`, `content_type: application/pdf`; the gateway takes the `pdf` row.

Vendor contracts: Firecrawl `POST https://api.firecrawl.dev/v1/scrape` with `{"url": …, "formats": ["rawHtml"], "onlyMainContent": false}` → `data.rawHtml` is the raw, `data.metadata.statusCode` is the target status (recorded as `http_status`), a missing `rawHtml` is a fetcher failure (markdown is never accepted as a raw); Jina `GET https://r.jina.ai/<url>` with `X-Return-Format: html`, `X-No-Cache: true` → the body is the raw, the target status from `X-Status-Code`/the body header when present, else `null`. Both: the key in `Authorization: Bearer …` to the vendor only; a 4xx/5xx from the vendor = that fetcher failed (recorded, next fetcher).

The report `mnemon-fetch/1`: `{schema, url, fetch_url, canonical_url, canonical_version, kind, requested_version, final_url|null, method, raw_kind, http_status|null, content_type|null, charset|null, bytes, egress: "direct"|"external", stages: [{stage, outcome, kind|null, status|null, bytes, elapsed_ms, note}], acquisition: {outcome, kind|null, evidence|null, visible_words}, metadata: {title|null, authors: [], published|null, published_source|null, arxiv_id|null, arxiv_version|null, arxiv_requested_version|null, declared_canonical_url|null}, hops: [...], elapsed_ms, error_class|null, error|null, retryable|null, stage|null, policy: {user_agent, max_bytes, max_redirects, connect_timeout, read_timeout}}`. Exit codes: 0 fetched; 1 failed (the report has `error_class`, `retryable`); 2 usage or `invalid-url`; 3 environment (no renderer where one was required and nothing else allowed); 124 timeout (`error_class: timeout`, `stage`).

### 3.4 Check — `capture/check.py`

`acquisition(status: int | None, headers, body: bytes, *, thin_words) -> Acq(outcome, kind, evidence, visible_words, title)`. **The decision table, first match wins** (`W` = visible words of the body after `<script>`/`<style>`/`<noscript>` removal; `WALL_MAX_WORDS = 200`; markers are case-insensitive substrings of the body or of a response header):

| # | Condition | outcome / kind | chain | retryable |
|---|---|---|---|---|
| 1 | `status == 429` and a bot-wall marker | `bot-wall` | escalate (the renderer once, then external when allowed) | no |
| 1 | `status == 429` otherwise | `rate-limit` | stop, fail | yes |
| 2 | `status == 503` and (`Retry-After` or a bot-wall marker) | `rate-limit` / `bot-wall` by the marker | fail / escalate | yes / — |
| 3 | `status == 503` otherwise, or `status in 500..599` | `unavailable` / `server-error` | stop, fail | yes |
| 4 | `status == 401` | `login` | stop, fail | no |
| 5 | `status == 407` | `forbidden` | escalate | no |
| 6 | `status == 403` and a bot-wall marker | `bot-wall` | escalate | no |
| 7 | `status == 403` | `forbidden` | escalate | no |
| 8 | `status in (404, 410)` | `not-found` | stop, fail | no |
| 9 | other `status >= 400` | `http` (`evidence: status`) | stop, fail | no |
| 10 | `status is None or 2xx`, a login marker and `W < WALL_MAX_WORDS` | `login` | stop, fail | no |
| 11 | a paywall marker and `W >= thin_words` | `paywall` | stop, publish as `blocked` | — |
| 12 | a paywall marker and `W < thin_words` | `login` (nothing readable) | stop, fail | no |
| 13 | a bot-wall marker and `W < WALL_MAX_WORDS` | `bot-wall` | escalate | no |
| 14 | js-shell signals (an empty root `#root`/`#app`/`#__next`/`#__nuxt`, or script bytes > 60 % of the body, or a `<noscript>` naming JavaScript) and `W < 30` | `js-shell` | escalate | — |
| 15 | `W < thin_words` | `thin` | render once, keep the richer | — |
| 16 | otherwise | `ok` | done | — |

Markers — bot-wall: `cf-chl`, `challenge-platform`, "just a moment", "attention required", "vercel security checkpoint", "access denied", "verify you are human", `_incapsula_`, "please enable javascript and cookies", "checking your browser", `px-captcha`, `datadome`, "request blocked"; login: "sign in to continue", "log in to view", "login to continue", "you must be logged in", a single `<form>` with a password field and `W < WALL_MAX_WORDS`; paywall: "subscribe to continue reading", "this post is for paid subscribers", "continue reading with a subscription", "subscribers only", `class="paywall"`, `data-paywall`, `id="paywall"`. A `PolicyError` never reaches the table: its kind is the class (`timeout`/`connection`/`tls` retryable; `ssrf-*`/`too-large`/`scheme` permanent). The rendered stage enters the table with `status = None`.

The classification is **one linear pass over at most the first 1 MB of the body** (`CLASSIFY_MAX_BYTES`): `W`, the title, the markers and the js-shell signals all come from that prefix, found by a small state machine driven by `str.find` — never by a regex with `.*?` or `[^>]*` over the whole document. An unclosed tag ends the pass and an unclosed `<script>`, `<style>`, `<noscript>`, `<template>` or `<title>` swallows the rest, as in a browser, so a hostile page costs one pass whatever its shape and can never hold the acquisition — and the vault lock — in in-process CPU time that no deadline interrupts (D11). The same bounded helpers serve the sanitizer's HTML level and the fetch chain's metadata scans.

`conversion(candidate_md, reference, title) -> Conv(missing: [str], glued: [str], headings_missing: [str], reference_count, eligible_count)` per D7; `inventory(subtree_html, md) -> {headings, list_items, tables, code_blocks, links, images}` each `{html: n, md: n}`; `outcome(acq, conv, inventory) -> complete | partial | blocked | unknown`: `unknown` when `eligible_count == 0`; `blocked` when `acq.kind == paywall`; `partial` when any of `missing`, `glued`, `headings_missing` is non-empty or `tables.md < tables.html` or `code_blocks.md < code_blocks.html`; else `complete`. Headings, lists, links and images are recorded, not judged.

Known limits, stated in the report's `limits` list: lines under six words that are not headings, table cells, equations and operators are not required; the `CHROME` regex can hide a short substantive line (it is restricted to lines of ≤ 12 words for that reason).

### 3.5 Convert and sanitize — `capture/convert.py`, `capture/sanitize.py`, `bin/capture-text.py`

```
capture-text.py <raw> --url <url> --out <file> --report <json> [--fetch-report <json>] [--raw-kind response|rendered|site|external]
                [--kind page|arxiv|youtube|github] [--rendered <file>]   # --rendered: the phase-1 legacy text path, kept
```

Inputs that only the fetch knew come from `--fetch-report` (the receipt's copy on a reconversion): `charset` (the `Content-Type` charset, used when the bytes carry no BOM or `<meta charset>`), `acquisition`, `egress`, `metadata` (arXiv authors, dates, versions, the declared canonical). Dated candidates (D8): the converter reports `published_candidates: [{value, source: citation_date | article:published_time | jsonld:<type> | og:…}]`; the gateway chooses by `SOURCE_TYPE` (never for `website`/site captures).

The report `mnemon-capture-text/2`: the `/1` keys (`schema`, `url`, `method`, `bytes`, `words`, `title`, `completeness`, `tool`, `error_class`, `error`) plus `retryable` (`null` on success; on a failure whether a retry can help — `false` for `nesting`, a document nested past what any parse can finish; the gateway honours it), `converter` (`defuddle` | `pandoc` | `dom-text` | `render-text` | `text`), `acquisition` (copied from the fetch report or `unknown`), `candidates: [{converter, missing_count, glued_count, headings_missing_count, chosen, note}]`, `reference_count`, `eligible_count`, `missing_count`, `glued_count`, `headings_missing_count`, `missing_examples` (≤ 5, ≤ 120 chars each), `inventory`, `repairs: {html: {svg_diagrams, svg_icons, latexml_listings, data_links, tables_rewritten, tables_unrepaired, math_sources}, markdown: {data_uris, data_links, next_images, tcolorbox_residue, residue_lines, comment_sections, tables_unrepaired}}` (the markdown counts are the chosen candidate's), `bytes_per_word`, `bloat`, `published_candidates`, `authors`, `arxiv_id`, `arxiv_version`, `arxiv_requested_version`, `limits`, `tools: {defuddle, pandoc}`. `method` keeps the phase-1 form `<fetch>+<converter>` (`direct+defuddle`, `render+pandoc`, `firecrawl+dom-text`, `site+mixed`); the gateway composes it from the two reports.

### 3.6 Site — `capture/site.py`, `bin/capture-site.py`, `mnemon site`

```
mnemon [--instance I] site map <url> [--max-pages N] [--include <regex>]… [--exclude <regex>]… [--out <plan.json>] [--json]
capture-site.py map <url> … --out <plan.json>
capture-site.py fetch-bundle <plan.json> --out <staged bundle dir> --report <json> [--site-timeout S] [--policy <json>] [--render-cmd …] [--external …]
capture-site.py verify <bundle dir> --sha256 <expected manifest sha256>
capture-site.py assemble <bundle dir> --out <capture.md> --report <json>
mnemon add --url <landing> --site <plan.json | auto> [other add flags]
```

`verify` is the bundle verification the gateway runs before every commit and every reconversion: exit 0 when the manifest's canonical bytes hash to the expected value and every member is present with its recorded size and hash, no symlink and no escaping path; exit 1 with `evidence-missing <member>` or `evidence-mismatch <member|manifest>` on stderr otherwise.

**Host eligibility** (no public-suffix guessing): a candidate is same-site when its host, after stripping one leading `www.`, equals the landing's; or when it is `docs.`, `help.`, `developer.`, `developers.`, `blog.`, `api.`, `learn.`, `support.` + the landing's host (also `www.`-stripped); or when the plan lists it explicitly (hand-edited plans may add a host; `mnemon add` prints the added hosts). Redirects to another host exclude the page (`excluded: redirect-off-site`). A GitHub repository linked from the landing contributes its README only (role `github_readme`, text).

**Discovery** (each source recorded with its yield): the landing's same-site links (after rendering when the landing is `js-shell`); `/sitemap.xml` and every `Sitemap:` of `/robots.txt`, sitemap indexes followed one level; `/llms.txt` when it is text and not the landing shell; docs tables of contents (`HelpTOC.json` of Writerside; the links of the first `/docs` page); the linked GitHub README. **Robots**: the `robots.txt` group chosen as RFC 9309 says (the most specific `User-agent` match, else `*`), `Allow`/`Disallow` by longest match, an unreadable `robots.txt` (fetch failure) = no rules, a 401/403 on `robots.txt` = everything disallowed; a disallowed page is `excluded: robots` and **a plan cannot include it**; `mnemon add --site` revalidates robots and the caps when it consumes a plan.

**Roles** by path and title rules, anchored, in this order: `job` (`^/jobs/[^/]+$`, `^/careers/[^/]+$`) · `careers` (`^/careers/?$`, `^/jobs/?$`) · `legal` (`/privacy`, `/terms`, `/legal`, `/cookie`, `/imprint`, `/eula`, `/gdpr`) · `localized` (a path segment or subdomain that is a locale tag such as `de-de`, `fr`, `ja`, `zh-cn` — excluded) · `howto` (`/troubleshooting`, `/faq`, `/changelog`, `/release-notes`; titles starting with "How to", "Install", "Getting started with Git") · `blog` (`/blog/`, `/posts/`, `/news/`) · `docs` (`/docs`, `/help`, `/guide`, `/manual`, `/reference`) · `pricing` · `product` (every other same-site page one or two segments deep) · `other`. Included by default: `landing`, `product`, `docs`, `blog`, `pricing`, `careers`, `job`, `github_readme`; excluded: `legal`, `localized`, `howto`, `other`; **`--include` restricts** (G21): with any include regex the plan keeps the landing and only the pages whose URL path (plus query) matches some include regex (a matching page the rules excluded by role is re-admitted; robots and content-type exclusions stand); `--exclude` then removes; the cap applies last. The cap `site_max_pages` (default 40) keeps pages by role priority (landing → product → docs → pricing → blog → careers → job → github_readme), the rest `excluded: cap`. Non-HTML pages (a PDF link, a binary) are `excluded: content-type`.

The plan `mnemon-site-plan/1`: `{schema, landing, created, discovery: {sources: [{name, yield, note}], robots: {fetched, groups, rules_applied}}, hosts: [...], pages: [{n, url, canonical_url, role, include, reason, title, discovered_by, render: bool|null}], caps: {max_pages}}` — editable by hand before `mnemon add --site`; `mnemon add` refuses a plan whose landing differs from `--url` (exit 2), whose included pages exceed the cap, or that includes a robots-disallowed page.

**`fetch-bundle`** owns the loop and its deadline: for each included page in plan order it runs the chain of §3.3 (the landing first; a landing that fails is fatal, exit 1 with its class; every other failure is recorded and the loop continues), writes `NN.html` + `NN.fetch.json` (NN = the plan's `n`, zero-padded), keeps ≥ 1 s between requests to one host, and stops at `site_timeout` with the remaining pages `skipped-timeout`; then `plan.json` (a byte copy of the input plan) and `manifest.json` last. **Manifest** `mnemon-site-bundle/1`: `{schema, landing, created, pages: [{n, url, role, file|null, fetch_report|null, sha256|null, bytes|null, disposition: captured|fetch-failed|skipped-timeout, error_class|null, error|null, raw_kind|null, http_status|null}], members: [{path, bytes, sha256}]}` where `members` lists **every file of the bundle except the manifest** (`NN.html`, `NN.fetch.json`, `plan.json`), paths relative, no `..`, no symlinks (refused on write and on read); the manifest bytes are canonical JSON (keys sorted, `separators=(",", ":")`, `ensure_ascii=False`, UTF-8, one trailing newline); `raw_sha256` = sha256 of those bytes; `raw_bytes` = the sum of `members[].bytes`. The CLI prints `raw_sha256` and `raw_bytes` on stdout. A bundle is **verified** by recomputing the manifest hash against the receipt and every member's hash against the manifest; any difference is `evidence-mismatch`, a missing member `evidence-missing` (the phase-1 rows, applied to directories).

**`assemble`** converts every `captured` page in-process (`capture-text.py` logic with `raw_kind: site` and that page's `NN.fetch.json` as the fetch report; `github_readme` and `llms.txt` pages are text, `converter: text`), writes the composite:

```
# <landing title> — site capture

## Part 1 — <landing url>

<page text>

## Part 2 — <url> (<role>)

<page text>
```

and the report `mnemon-site/1`: `{schema, pages: [{n, url, role, disposition: captured|convert-failed|fetch-failed|skipped-timeout, converter, completeness, missing_count, glued_count, words, bytes, error_class, error}], included, captured, completeness, words, bytes}`; a page whose conversion fails is `convert-failed` and omitted from the composite (recorded). **Aggregate completeness**: `complete` when `captured == included` and every captured page is `complete`; `blocked` when the landing is `paywall`; `partial` otherwise. The gateway writes `folded_sources:` (one entry per planned, included page after the landing: `url`, `role`, `disposition`, `converter`, `completeness`, `missing_lines`), `site_pages: "<captured>/<included>"`, `capture.raw_kind: site`, `capture.completeness` = the aggregate, `method: site+mixed` (or `site+<converter>` when one converter served every captured part). `cap_reconvert` for `raw_kind: site` verifies the bundle and runs `assemble`, never the network. A site-wide timeout publishes a partial bundle when the landing was captured, else fails `timeout`.

### 3.7 Media — `bin/media-extract.py`

- `--timeout <s>` (D11): the caption fetch runs as `media-extract.py _captions <video_id> --out <file>` (a subprocess, so a hung library call is killable), yt-dlp, ffprobe and whisper as subprocesses; all in their own process group under one budget; on expiry: kill the group, reap, write `error.json` (`{schema: "mnemon-media-error/1", error_class: "timeout", stage: "download"|"probe"|"captions"|"transcribe", elapsed_s}`) under `--out-dir`, delete nothing, exit 124. ### 3.8 Chunked extraction (D13) — `bin/lib-capture.sh`, `bin/extract-publish.py`, templates

- `extract-publish.py split --in <capture.md> --max-bytes N --max-parts M --out-dir <dir>`: byte-preserving (parts concatenate to the input), split only at line boundaries outside fenced blocks (``` and ~~~ tracked), preferring `^#{1,3} ` lines, else blank lines, greedy packing; writes `part-<n>.md` and `parts.json` (`[{n, bytes, first_line}]`); exit 1 `unsupported-size` when a single unsplittable span exceeds N or the count exceeds M.

- `templates/core/_part.md`: IDENTITY, STEPS (Pass 1 only: ideas and quotes of this part; no rating, no connections), the Fields of `extract-part/1`, a marker line `<!-- mnemon:part-template -->` (the stub `claude` keys on it), no Body section.
- `cap_extract`: when `text_bytes > EXTRACT_INLINE_MAX_BYTES` → `split`; per part: the phase-1 §4.5 prompt in **part mode** (its OUTPUT paragraph replaced by: "Return the structured fields of `extract-part/1` for this part only: a title, a summary, the key ideas as standalone claims with a domain each, and verbatim quotes. No body, no rating.") with the part as CONTENT and `_part.md` as the template, `extract-run.py` in `parts/part-<n>/` (its own `prompt.md`, `result.json`, `stderr.txt`, `argv.json`), `validate-part`; then the merge in `merge/`: the §4.5 prompt with `=== PART EXTRACTS (N) ===` (each part rendered: `## Part n — <title>`, the summary, the claims as `- claim #domain`, the quotes as `> …`) in place of `=== CONTENT ===`, the main template, schema `extract/1`, published as today. **Budget**: `spent` = the sum of `total_cost_usd` of every finished call in this capture (parts, merge, validation retries, failed calls that reported a cost; a null cost is counted as 0 and sets `cost_unknown: true`), kept in the receipt (`calls: [{kind: part|merge, n, attempt, cost_usd, duration_ms, result}]`, `cost_usd` = spent); each call gets `--max-budget-usd` = `extract_max_usd − spent` and is not started when that is ≤ 0 (`budget-exhausted`, `extract-failed`, retryable only with a raised budget); without `extract_max_usd` no cap, as today. Merge input size = the bytes of the rendered part extracts; above the inline limit → `unsupported-size`. `extract.md` frontmatter: `extraction: single|chunked`, `parts: N` (from `--meta`). A part failure → `extract-failed` with its class; `--resume` re-runs all parts (no cache; the budget continues). `--dry-run`: for `text`/`file` origins the part plan (sizes) is printed; for URL origins "chunking decided after acquisition".

### 3.9 Index — `bin/knowledge-reindex.py` (D14)

- Every row is generated; `index_note` (`extract.md`, one line, the §4.4 subset, decoded and display-escaped like titles) appended as ` — <note>`; **derived** `superseded`: a scan of every `source.md`'s `supersedes:` (`<revision>` or `Sources/<revision>/extract`) builds `old → [new…]`; a superseded row gets ` ⤳ superseded by [[Sources/<new>/extract|<new title>]]` per successor (fan-out lists each; a successor without `extract.md` links `[[Sources/<new>/source|…]]`; a missing successor folder prints `(missing: <new>)`; a cycle is reported on stderr and not marked); the counters line reports `Superseded=N` (its `Key=N` form, beside `Pending`, `Legacy`, `Dangling-supersedes`, `Preserved`, `Malformed-frontmatter` when non-zero).
- **Preservation transaction**: the regenerated rows are compared with the existing ones by exact text after stripping the derived suffix (` ⤳ …`) and the `index_note` suffix from both; every differing existing row is appended under a dated heading to `<vault>/_inputs/index-hand-edits-<YYYY-MM-DD>.md` (one entry per folder per file; `_inputs/` created if absent), the file fsynced; only then is `index.md` replaced (tmp + fsync + rename); if the report cannot be written the index is left untouched and the run exits 1 with the reason; `--no-hand-edit-report` skips the preservation (explicit).
- The pending note: `_N source(s) captured without extract.md (finish with `mnemon add --resume <revision>`)._`; legacy placeholders (`status: bookmark`, `fetch_status: failed` in `source.md`) counted apart.
- `mnemon status` (in `knowledge-gateway.sh`) reports `superseded` (from the same `supersedes:` scan of `source.md` files) and `chunked` (`extract.md` with `extraction: chunked`).

## 4. Gateway integration — `bin/lib-capture.sh`, `bin/knowledge-gateway.sh`

### 4.1 Identity and lookup (D5)

### 4.2 Dispatch precedence (acquisition of a url origin)

1. `--site` → §3.6 (`cap_acquire_site`); nothing else runs.
2. `kind: arxiv` → `capture-fetch.py` with the resolver's version logic, `--kind arxiv`, `source_type` default `paper`; no depth fold.
3. `origin: youtube` → the media path (unchanged, plus D12); no depth fold.

## 11. Answers to the review's questions

- A site plan is an acquisition mode of the landing resource; a landing with an existing revision needs `--recapture` (the site revision `supersedes` it).
- Several heads: the candidate not superseded by another with the greatest `(captured date, numeric suffix, folder name)` — deterministic, stated in §4.1.
- "No cookies" prohibits supplied or persisted credentials and cookie jars in the engine; anonymous cookies Chrome creates during one render live in a throw-away profile and die with it.
- A site-wide timeout publishes an explicitly partial bundle when the landing was captured; otherwise the acquisition fails `timeout`.
- The extraction budget covers the capture operation's lifetime (parts, merge, retries, resumes).
- What survives loss of machine-local state when the archive remains: the raw (file or bundle with plan and fetch reports), the frozen `<revision>.report.json`, and the frontmatter summary; the receipt (ledger) is local and re-derivable only for the facts those carry — stated in `docs/capture.md`.

## 12. Amendments v2.1 (binding)

The second external review (`20261015T223620`, 794 s) accepted v2 with twelve amendments and no redesign. They bind where they differ from §2–§7; owners as in §10. A12 is applied in this document before implementation starts (shared contracts and fixtures); the rest are applied by their owners and checked by the integrator.

### A1 — Lossless index preservation (C)

Every existing row whose **exact text** differs from the regenerated row is preserved — no suffix stripping decides anything; preserved rows are deduplicated by `(folder, sha256(old row))` across the day's file, so a second edit on the same day is preserved too; the preservation file **and its directory** are fsynced before `index.md` is replaced. Test: two edits of one row in one day → two entries.

### A2 — Aliases only from converted parts; lookups read whole headers; no silent "no resource" (B, A)

Only a `folded_sources` entry whose `disposition` is `converted` (A5) establishes an alias; entries with any other disposition are skipped by the lookup; entries **without** a disposition are legacy and count as aliases. The lookup reads each `source.md` **through the closing `---` delimiter** (cap 256 KB); a header without a closing delimiter or above the cap is reported on stderr as `malformed-frontmatter <folder>` and listed by `doctor captures`; it never silently truncates. When candidates exist but no head can be chosen (every candidate is superseded by another — a cycle) the capture exits 1 with `integrity-error`/`supersedes-cycle` naming the folders; it never proceeds as if no resource existed.

### A3 — Durable budget accounting (B)

Before every billable call (the single extraction, each part, the merge, every validation retry) the receipt records `calls[]: {id, kind: single|part|merge, n, attempt, state: reserved, reserved_usd, started_at}` (atomic receipt write); after the call it is reconciled **exactly once** (`state: done|failed, cost_usd, duration_ms, result`) before any other call starts. `spent` = the sum of reconciled `cost_usd`; with a finite `extract_max_usd`, a call whose cost is unknown (`cost_usd: null`) **keeps its reservation** (the remaining budget at launch) in `spent`, so further calls stop with `budget-unreconciled`; the operator reconciles with `mnemon add --resume <id> --assume-cost <usd>` (applies that cost to every unreconciled call, recorded as `assumed: true`); without a finite budget unknown costs are recorded with `cost_unknown: true` and nothing stops. A crash between a finished call and its debit: on resume the call's `result.json` in its directory reconciles it (`total_cost_usd`); absent → unknown cost, as above. Phase-1 receipts: their `cost_usd` is one reconciled `single` call. An alias delegates to the owner receipt's `calls`. `cap_extract` no longer passes the full budget per call or replaces `cost_usd`.

### A4 — The frozen request and the plan freeze point (B)

`mnemon-request/2` is this object, keys sorted, no whitespace, `ensure_ascii=false`: `{"schema":"mnemon-request/2","origin":<str>,"resource_kind":<str>,"resource_key":<str>,"input_sha256":<hex|null>,"url":<literal url|null>,"ref_path":<str|null>,"context":<str>,"source_type":<str|null>,"recapture":<bool>,"supersedes":<str|null>,"render":"auto"|"force"|"off","external":"auto"|"off","site":null|"auto"|<hex of the plan file>,"requested_version":<int|null>,"canonical_version":1,"depth":"auto"|"off"|"force"}` — seventeen keys: `render` is `force` on `--render`, `off` on `--no-render`, else `auto`; `external` is `off` on `--no-external` or when the instance says off, else `auto`; `site` is the plan file's sha256 for `--site <file>` (the file is read before the request is built, like `--file-text`), the literal `"auto"` for `--site auto`, `null` otherwise; `depth` is the `--depth` mode the phase-1 request already bound (`auto` by default, `force`, or `off` — always `off` for a site capture, where the fold never runs), kept because it changes what a capture folds in; the receipt fixtures `receipts/request-v2-*.json` carry it. For a non-URL origin `url` is `null` and the fields `render`, `external`, `site`, `requested_version` take their defaults. `cap_binding_check` reads `request.schema` from the receipt **first**, builds the comparison from the supplied arguments under that schema's rules (`/1`: the literal URL as `resource_key`, no new fields, the phase-1 defaults for origin autodetection and source type), never overwrites the supplied arguments, and only then compares. `site: "auto"`: the generated plan is written to `attempt-1/plan.json` and its sha256 recorded in the receipt as `site_plan_sha256` **before** `fetch-bundle` starts (acquisition metadata, not a bound field); the locator for a site capture is the plan (`input_path` = the given file or `attempt-1/plan.json`), retained with the receipt; recovery consults it only when no retained bundle serves the next step (the published bundle's `plan.json` wins — phase-1 A4). Tests: a crash before and after the plan freeze; the original plan deleted or changed after publication (bundle wins); ID-only replay; explicit `--resume`. Receipt golden fixtures `tests/fixtures/capture/receipts/{request-v1,request-v2-page,request-v2-site-auto}.json` (A12).

### A5 — Acquisition dispositions in the bundle, conversion dispositions in the report; landing conversion fails publication; directory recovery (B, A)

The manifest holds **acquisition** dispositions only (`captured` = fetched, `fetch-failed`, `skipped-timeout`) and is immutable; **conversion** dispositions (`converted`, `convert-failed`) live in the assembly report and in `folded_sources`; `site_pages` = `"<converted>/<included>"`. A landing whose conversion fails or yields no text fails the publication (`convert`, exit 1, bundle retained; `--resume` reconverts). Directory recovery: `cap_cleanup_staging` removes a `.site.staging-*` directory only when no non-final receipt owns it (the existing receipt check extended to directories); staged and final trees are verified (`capture-site.py verify`) before collision reconciliation; `manifest.json` is fsynced like every member and the directory; phase-1 §12 A3 holds — a **published** bundle with a missing or changed member is `evidence-mismatch` (`evidence-missing` only for a recorded, never-published raw); §7.10 is read with that correction. A crash hook `after-raw-renamed` (before the receipt's `raw_published` update) is added and tested.

### A6 — The sidecar transaction; media metadata before the raw checkpoint (B)

Before the source is published the final report is frozen: canonical bytes written to `attempt-<n>/report.json`, `report_sha256`, `report_path` and `report_state: pending` recorded in the receipt. After the source directory rename the sidecar is staged in the archive and renamed; `report_state: published`. Recovery and replay: `pending` with an existing sidecar of the same hash → `published`; an existing sidecar with a different hash → `integrity-error`/`report-conflict`, revision retained; a missing sidecar → re-published from the frozen bytes (the attempt file, else the receipt's `capture_report` re-serialized; a hash that does not match `report_sha256` → `report-conflict`). A sidecar failure after the source exists never fails the capture: `RESULT:report=failed` (else `RESULT:report=ok`), `report_state` stays `pending`, repaired on the next replay; exit code unchanged. `media_meta` is recorded in the receipt **before** `cap_raw_commit` of the media raw (the YouTube path moves `cap_media_meta` ahead of the commit).

### A7 — Acquisition precedence, terminal transitions, `--expect` mapping (A, B)

The table of §3.4 is amended: (i) `login` and `paywall` rows are evaluated **before** the 403/407 rows — any status with a login marker and `W < WALL_MAX_WORDS` is `login`; a paywall marker is `paywall`/`login` by `W` as rows 11–12 say, whatever the status; (ii) 503 with `Retry-After` is `rate-limit` (terminal, retryable) whatever the markers; 503 with a bot-wall marker and no `Retry-After` is `bot-wall`; (iii) a renderer exit 124 is `timeout` (terminal, retryable, `stage: render`), never a transition to external; any other renderer failure or a `js-shell`/`bot-wall`/`forbidden` rendered result → stage 3; (iv) a `thin` direct result whose render is unavailable, fails or times out is **kept and published** (`acquisition: thin`); (v) a vendor's answer classified `rate-limit`, `login` or `paywall` is terminal for the whole chain (no next vendor); (vi) the outcome order is `blocked` → `unknown` → `partial`/`complete` (a paywall teaser with zero eligible lines is `blocked`). `--expect pdf|audio` has its own mapping and no escalation: 2xx with the expected type → done; 401/403/407 → `blocked`/`forbidden` (permanent); 404/410 → `not-found`; 429 → `rate-limit`; 5xx → `server-error`/`unavailable`; a 3xx without `Location` → `http`; the wrong type → `not-pdf`/`not-audio`. `--render` (forced) starts at stage 2; without Chrome it is `environment`.

### A8 — Depth enrichment under a frozen context (A, B)

The gateway passes the fold a frozen acquisition context (`--context <json>`: `final_url`, `http_status`, `acquisition`, `render: auto|off`, `external: off`, `budget_s`); with `--landing-file` the probe **never** fetches or renders the landing (the Chrome branch is removed under a supplied landing; `rendered` and `final_url` come from the context); `kb-depth-fold.py` no longer fetches the landing's markdown; its result lists only the folded targets (`targets: [{url, role, header, text, status, sha256}]`, `manifest_yaml`), and the gateway assembles `converted landing + targets` exactly once; a folded target whose response is non-2xx or classified as a wall by `check.acquisition` is rejected (`fold fetch rejected: <class>`), not folded. Completeness of a composite covers the landing only and the report says so.

### A9 — One cancellation hierarchy (A, C)

An owner creates each direct child in a new process group it tracks; on its own deadline or on SIGTERM from its parent it sends SIGTERM to every tracked child group, waits a 2 s grace, SIGKILLs what remains, reaps, and only then exits — so site → fetch → Chrome and depth → probe → renderer are torn down from the top. DNS resolution runs in a daemon thread bounded by the remaining deadline (abandoned on expiry, `timeout`). `capture-text.py --timeout` (`convert_timeout`, default 300) supervises `defuddle`/`pandoc`; `assemble` passes its remaining budget to each page's conversion. Tests: nested site → fetch → stub renderer and depth → probe → stub renderer, every descendant gone after the kill.

### A10 — Robots per RFC 9309 (A)

`robots.txt` **unreachable** (network error, 5xx) → everything disallowed (`excluded: robots-unreachable`, the plan says so); **unavailable** (any 4xx, including 401/403) → no rules; the product token is `mnemon` (groups whose `User-agent` matches it case-insensitively are merged; else the `*` groups merged); `Allow`/`Disallow` by longest match. Host and robots eligibility are applied **per hop** of a site page's redirects (the policy's hop callback), so an off-site or disallowed destination is excluded before it is fetched.

### A11 — Jina transport (A)

Hash routes (`#!…`, `#/…`) are sent as Jina documents for SPA routing — `POST https://r.jina.ai/` with the URL in the body; other URLs as `GET https://r.jina.ai/<url>`; both with `X-Return-Format: html` and `X-Respond-With: html` (the two header names the reader has documented) and `X-No-Cache: true`; a non-HTML body is a fetcher failure. The adapter is fixture-tested against recorded responses (no network).

### A12 — Shared interfaces and ownership frozen before implementation (all)

- `capture-fetch.py` accepts `--kind page|arxiv|youtube|github` (the gateway passes the kind from `--canonical-only`; `youtube` and `github` are `page` for fetching); the gateway's origin autodetection routes by `--canonical-only`'s `kind` (`youtube` → the media path, including embed/live/music forms); an explicit `--origin url` on a YouTube URL is a page capture (explicit wins); an explicit `--origin youtube` on a non-YouTube URL → exit 2.
- `capture-site.py fetch-bundle` accepts `--no-render`, `--no-external`, `--policy`, `--external`, `--fetch-timeout`, `--render-timeout`, `--acquire-timeout` (per page), `--site-timeout`; precedence: a global `--no-render` prohibits rendering everywhere (a plan's `pages[].render: true` cannot override it; `--no-render` also prohibits remote-rendering vendors — it means "no rendering", so it implies `--no-external`), otherwise `pages[].render: true` forces, `null` lets the chain decide.
- Report schemas: the fetch report gains `ext` (the sniffed audio extension, else null) and `audio_sniff` (the mime, else null); `fetch-bundle` prints exactly one JSON line `{"raw_sha256":"<hex>","raw_bytes":<int>}`; one example per schema, including failure and null shapes, lives in `tests/fixtures/capture/reports/` (`canonical.json`, `fetch-ok.json`, `fetch-failed.json`, `fetch-timeout.json`, `text.json`, `site-plan.json`, `site-manifest.json`, `site-report.json`, `media.json`, `media-error.json`, `receipts/*.json`); every producer validates its output against the fixture's key set in its own tests, every consumer reads the fixture in its tests; the integrator diffs real outputs against the fixtures.
- Part extraction: the part-mode prompt (§3.8) and the domain rule — each `key_ideas[].domain` must match the `extract/1` domain item regex (`[a-z0-9][a-z0-9_/-]*`), nothing else is validated.
- Ownership additions: `tests/test_chain.sh` → the integrator (migrated from the `curl` stub to the `capture-fetch.py` stub without weakening a recovery check); `tests/test_depth.sh` → A; B's temporary converter patch implements the frozen `/2` report contract of `reports/text.json`.

- Dry-run deferrals: for `--file` pdf/audio origins the chunk plan is deferred like URLs.
- Dates: when more than one distinct eligible date is found the gateway omits `published:` and records the candidates (`published_candidates` in the receipt).
- `--recapture` fills omitted pages of a published partial site capture; `--resume` only finishes extraction from retained evidence.
